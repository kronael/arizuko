twitd

twitd connects X to arizuko

twitd connects X, also known as Twitter, to arizuko, so the agent can read mentions and DMs and reply.

twitd is the X channel adapter. It wraps agent-twitter-client, the ai16z fork of @the-convocation/twitter-scraper, to drive X through browser emulation with cookies and no API key. It runs in TypeScript on Bun, with the JID prefix twitter:.

The web interface is the only usable path to X

The official v2 API of X costs too much for a small bot: the free tier cannot post tweets, mention users or send DMs. agent-twitter-client drives the same web interface that a logged-in user sees, which is the only path that works for arizuko deployments. X often suspends such accounts, and the README has a runbook for a lost account.

twitd sits between X and routd

X (twitter.com web surface)
        │  agent-twitter-client poll (mentions, DM convs)
        ▼
      twitd     (LISTEN_ADDR=:8080, Bun runtime)
        │  POST /v1/messages    (service:<daemon> ES256 bearer)
        ▼
      routd
        │  POST /send           (callback to twitd)
        ▼
      twitd     (sendTweet | sendDirectMessage | favorite | ...)
        │
        ▼
      X

twitd uses four JID forms:

twitter:home
The timeline and mentions.
twitter:tweet/<id>
One tweet.
twitter:dm/<conv_id>
One DM thread.
twitter:user/<handle>
One profile.

The wired verbs are in twitd/src/verbs.ts:

send
A DM through sendDirectMessage.
post
A tweet.
reply
sendTweet(text, replyToId).
repost
A retweet.
quote
A quote tweet. An empty body returns a hint to use repost.
like
A favorite, on or off, with no emoji.
delete
Own tweets.
send_file
An image or video for tweets. In DMs, the attachment becomes text only.

forward, dislike and edit return 501 with a hint, because X has no downvote and the library does not expose the edit of X Premium.

X has no stream for this client, so twitd polls mentions every TWITTER_POLL_INTERVAL seconds, 90 by default.

twitd tries three login methods in order

  1. A cookie file at $TWITTER_AUTH_DIR/cookies.json, exported from a logged-in browser. This method is recommended, because it skips 2FA.
  2. Username and password in TWITTER_USERNAME, TWITTER_PASSWORD, TWITTER_EMAIL and TWITTER_2FA_SECRET. twitd uses them only when the cookies are missing or not valid, and it saves the cookies after a successful login.
  3. Pair mode: bun dist/main.js --pair logs in with the credentials from the environment, saves the cookies and exits. Use it to prepare the cookies before the first start.

On every save, twitd rotates the cookies atomically to cookies.json.bak.

twitd runs alone with routd and a cookie file

export ROUTER_URL=http://routd:8080
export AUTHD_URL=http://authd:8080
export AUTHD_SERVICE_KEY=$(grep ^AUTHD_SERVICE_KEY .env | cut -d= -f2)
export LISTEN_ADDR=:8080
export TWITTER_AUTH_DIR=/srv/data/store/twitter-auth
export TWITTER_POLL_INTERVAL=90
# either: drop a cookies.json into TWITTER_AUTH_DIR, or:
export TWITTER_USERNAME=<user>  TWITTER_PASSWORD=<password>  TWITTER_EMAIL=<email>
bun dist/main.js

GET /health returns 503 with {status:"disconnected"} while twitd is not logged in. It also returns 503 with {status:"stale"} when no inbound message arrived for 5 minutes. If the cookies expired, put a new cookies.json in place and restart twitd. If the password login hits a 2FA challenge, use the cookie method.

One person maintains the library, agent-twitter-client@0.0.18. Pin the version, so a breakage on the X side stays out of the dependency graph until the operator decides to upgrade.
