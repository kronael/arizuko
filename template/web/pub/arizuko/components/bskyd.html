bskyd

bskyd polls Bluesky for mentions and replies, and writes the answers of the agent as Bluesky records.

bskyd connects Bluesky to arizuko

bskyd connects Bluesky to arizuko, so the agent can read mentions and reply with posts.

bskyd is the Bluesky channel adapter. It polls Bluesky notifications through the AT Protocol xrpc API for mentions and replies, and posts them to routd. It writes outbound messages as app.bsky.feed.* records on the personal data server, the PDS, of the account. The JID prefix is bluesky:. An account has the JID bluesky:user/<did>, with the colons of the DID percent-encoded.

Bluesky has no stream for one account, so bskyd polls

Bluesky is the social network of the AT Protocol. It has no streaming API for one account: the firehose covers the whole network and has too much noise. So bskyd polls listNotifications and refreshes its auth session in a loop. To post, bskyd signs record creates against the PDS for the agent.

bskyd sits between the PDS and routd

Bluesky PDS (bsky.social or custom)
        │  xrpc poll: app.bsky.notification.listNotifications
        ▼
      bskyd     (LISTEN_ADDR=:8080)
        │  POST /v1/messages    (service:<daemon> ES256 bearer)
        ▼
      routd
        │  POST /send           (callback to bskyd)
        ▼
      bskyd     (com.atproto.repo.createRecord on app.bsky.feed.*)
        │
        ▼
      Bluesky PDS

The wired verbs are in bskyd/client.go and bskyd/server.go:

send, reply
app.bsky.feed.post. reply_to sets the reply reference.
send_file
uploadBlob and app.bsky.embed.images, one image.
post
A post with media_paths[0] embedded.
like
An app.bsky.feed.like record.
delete
com.atproto.repo.deleteRecord.
quote
app.bsky.embed.record.
repost
An app.bsky.feed.repost record.

dislike, forward and edit return 501 with a hint.

The edit hint is deliberate. putRecord succeeds at the PDS, but the Bluesky appview ignores updates to app.bsky.feed.post records on purpose, so the edit never appears in the feed. Use delete and then post instead.

Inbound messages come only from the public feed. DMs would need chat.bsky.convo through did:web:api.bsky.chat, and no inbound DM polling exists.

bskyd runs alone with routd and an app password

bskyd is a plain Go binary. It needs a reachable routd, a Bluesky handle and an app password, not your main password.

export ROUTER_URL=http://routd:8080
export AUTHD_URL=http://authd:8080
export AUTHD_SERVICE_KEY=$(grep ^AUTHD_SERVICE_KEY .env | cut -d= -f2)
export LISTEN_ADDR=:8080
export BLUESKY_IDENTIFIER=you.bsky.social
export BLUESKY_PASSWORD=abcd-efgh-ijkl-mnop    # app password
export BLUESKY_SERVICE=https://bsky.social     # or your PDS
export DATA_DIR=/srv/data/arizuko_demo
./bskyd

On the Bluesky side, open Settings, Privacy and security, App passwords. An app password skips 2FA, and you can revoke each one alone. GET /health returns 503 when the auth session is not valid. bskyd refreshes the session automatically and recovers on the next poll.
