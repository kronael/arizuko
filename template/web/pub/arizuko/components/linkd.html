linkd

linkd posts, comments, likes, reshares and deletes as the bot account, through the part of the LinkedIn API that needs no partner approval.

linkd lets the agent act on its own LinkedIn posts

linkd lets an agent act on LinkedIn with the own posts of the bot account: post, comment, like, reshare and delete.

linkd is the LinkedIn channel adapter. It uses the LinkedIn v2 community-management API for the own shares and comments of the bot account: UGC posts, likes, reshares, comments and deletes. The JID prefix is linkedin:.

linkd uses the part of LinkedIn that needs no partner approval

LinkedIn DMs and company-page posts need OAuth scopes that only partners get, and arizuko deployments cannot get them. linkd uses the part that works with w_member_social: the own UGC posts of the agent and the social actions on them. For the rest, it returns structured hints, so the agent gets a concrete alternative and not a silent failure.

linkd sits between LinkedIn and routd

LinkedIn (api.linkedin.com)
        │  poll: own UGC shares + comments, every LINKEDIN_POLL_INTERVAL
        ▼
      linkd     (LISTEN_ADDR=:8080)
        │  POST /v1/messages    (service:<daemon> ES256 bearer)
        ▼
      routd
        │  POST /send           (callback to linkd)
        ▼
      linkd     (REST: /v2/ugcPosts | /v2/socialActions/{urn}/...)
        │
        ▼
      LinkedIn

The wired verbs are in linkd/client.go:

send, reply
A comment on a post URN, POST /v2/socialActions/{urn}/comments. When LINKEDIN_AUTO_PUBLISH=true, send to a JID that is not a comment publishes a ugcPost.
post
/v2/ugcPosts.
like
/v2/socialActions/{urn}/likes.
delete
DELETE /v2/ugcPosts/{urn} for own posts.
repost
/v2/ugcPosts with referenceUgcPost.
fetch_history
The comments on a post URN.

send_file, forward, quote, dislike and edit return 501 with a hint.

An edit of a UGC post needs the versioned /rest/posts PARTIAL_UPDATE flow, which linkd does not implement. send_file needs /assets registerUpload and a binary PUT, which linkd does not implement either.

linkd runs alone with routd and a LinkedIn app

linkd is a plain Go binary. It needs a reachable routd and a LinkedIn application with member-social scopes. On a 401, linkd refreshes the access token automatically with the refresh token.

export ROUTER_URL=http://routd:8080
export AUTHD_URL=http://authd:8080
export AUTHD_SERVICE_KEY=$(grep ^AUTHD_SERVICE_KEY .env | cut -d= -f2)
export LISTEN_ADDR=:8080
export LINKEDIN_CLIENT_ID=<client id>
export LINKEDIN_CLIENT_SECRET=<client secret>
export LINKEDIN_ACCESS_TOKEN=<access token>
export LINKEDIN_REFRESH_TOKEN=<refresh token>
export LINKEDIN_POLL_INTERVAL=300s
export LINKEDIN_AUTO_PUBLISH=false
./linkd

On the LinkedIn side, register an app at linkedin.com/developers with the scopes r_liteprofile and w_member_social. Run the OAuth code flow once to get the first access and refresh tokens, and copy them into the environment. Company-page posts and DMs both need partner approval and are out of scope by design.

GET /health returns 503 when the access token has expired and the refresh fails.
