components

An arizuko deployment is a set of small programs, and each program does one job. A daemon is such a program that runs in the background. Every instance runs the core daemons. Channel adapters connect outside platforms such as Slack or Telegram, and an instance runs the adapters it needs. Each row links to the page of that program.

The core daemons run in every instance

namerole
routdThe routing plane. It runs the message loop, resolves each event to a group, hosts the agent MCP socket, and owns the routd.* tables and the grant authority. See concepts/routing.
runedThe execution plane. It starts and stops the KVM guest of each turn, is the only daemon with /dev/kvm, and owns the runed.* tables.
authdThe auth plane. It creates and verifies tokens, serves the OAuth provider routes, and owns the authd.* tables. See concepts/auth.
webdThe web channel: the SSE hub, the route-token URLs and the MCP endpoint.
proxydThe reverse proxy with auth. It verifies JWTs and signs identity headers for backends.
vitedThe static origin, a Vite server behind proxyd for the /pub/ docs and the web pages of groups.
dashdThe operator dashboard, to browse groups, grants and messages in a browser.
onbodThe onboarding daemon: the pairing greeting, the admission queue and invite tokens.
timedThe scheduler. It claims due tasks over the HTTP API of routd and posts each prompt as a message. It opens no store of its own.
ttsdThe text-to-speech proxy, an endpoint compatible with OpenAI for voice replies.
davdThe WebDAV server, to mount the folder of a group in a file manager.
route tokensThe /chat/<token>/ visitor chat and the /hook/<token> webhook intake, both served by webd.
egressThe forward proxy: one per turn, with one fixed host allowlist and one client. runed starts it and stops it with the turn.
litellmThe model gateway package. It holds the model credential, and the guest of each turn gets a virtual key. It writes one JSON log line per request and sends token and cost spans over OTLP.

Channel adapters connect outside platforms

namerole
channelsThe overview: the shape that all adapters share, their common HTTP endpoints, and how to add an adapter.
slakdSlack: an Events API listener, a bot user and threaded replies.
teledTelegram: the Bot API, groups and DMs, voice and media.
discdDiscord: a gateway client, server channels and threads.
bskydBluesky: polls the AT Protocol notifications for mentions and replies.
reditdReddit: subreddit and inbox polling, comments and DMs.
emaidEmail: IMAP in, SMTP out, and threads by message-id.
linkdLinkedIn: the messaging API and DMs with connections.
whapdWhatsApp: a TypeScript adapter on Baileys, with a QR or pairing-code login.
twitdX: a TypeScript adapter for mentions and DMs.
gitdGitHub: signed webhook intake. The agent answers through the GitHub MCP connector.
