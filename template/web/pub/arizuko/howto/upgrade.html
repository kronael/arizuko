arizuko › howto › Upgrade

upgrade

An upgrade builds the images from the new checkout and restarts the instance. Each of the two guest artifacts goes into a new directory, and .env must name the new directory.

Eight commands upgrade an instance

Run the commands in the arizuko checkout. Replace demo with the name of the instance.

git pull                                          # the new release
make build                                        # ./arizuko + daemon binaries
sudo make images DATA_DIR=/srv/data/arizuko_demo  # prints rootfs: <dir>
sudo make kernel DATA_DIR=/srv/data/arizuko_demo  # prints kernel: <dir>
sudoedit /srv/data/arizuko_demo/.env              # RUNED_ROOTFS_DIR, RUNED_KERNEL_DIR
./arizuko generate demo                           # read every warning it prints
sudo systemctl restart arizuko_demo               # arizuko run regenerates, starts
./arizuko send demo main "ping" --wait            # one reply proves the path

Each artifact goes into a new directory

A turn starts a guest kernel and a root filesystem from the data directory. The name of each directory contains a hash of its content. runed reads the two paths from .env:

make images ──► DATA_DIR/images/rootfs-<image id>/        ◄── RUNED_ROOTFS_DIR
make kernel ──► DATA_DIR/images/kernel-<version>-<hash>/  ◄── RUNED_KERNEL_DIR

make images exports a new rootfs tree only when the arizuko-ant image changed. It prints the directory in both cases. It deletes no tree. make rootfs-stale lists the trees after the newest two, and you remove them. make kernel builds only when kernel/Dockerfile, kernel/arizuko.fragment, kernel/check-config.sh or kernel/guest-init/*.go changed. In all other cases it prints is current, and RUNED_KERNEL_DIR does not change.

When RUNED_ROOTFS_DIR keeps the old value, the new daemons start the guest of the previous release. No error occurs.

arizuko generate shows its warnings before the restart

systemctl restart runs arizuko run, and arizuko run writes the compose file again. arizuko generate before the restart shows its warnings on the terminal, not in the journal. Two warnings need a fix before the restart: a FROZEN fragment, and a daemon without a store key. A daemon without a store key restarts the whole instance in a loop.

A release queues one /migrate turn for each folder

When a release increases MIGRATION_VERSION, routd queues one /migrate turn for each folder with old skills. Other messages wait behind these turns, so the first replies after an upgrade are slow. The queue is empty when no guest runs:

pgrep -c qemu-system-x86    # prints 0 when the /migrate turns are done

The older rootfs tree rolls back the guest

The older rootfs tree stays on disk. Set RUNED_ROOTFS_DIR to the older tree and restart. The daemons keep the new images. A rollback of the daemons needs a build from the old checkout.

Five gates end a release

A maintainer release runs the five post-deploy gates in [gates.md]. Only the last gate, anteval --smoke, shows that a live agent answers. Run it after the /migrate turns end. Before that, it measures the queue and not the release.
