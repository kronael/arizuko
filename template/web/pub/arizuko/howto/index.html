getting started

This guide takes a new host to a running instance with one channel and one invited user. One block of commands does the install. The sections after the block explain each part. The section Eight terms recur in these guides defines group, agent, turn, channel, skill, grant, JID and route token.

The host needs KVM, Docker, Go and enough memory

  • A Linux x86_64 host where you can use sudo. The tests run on Debian 12.
  • Docker with Compose v2.20 or newer. The daemons, the background programs of arizuko, run as Docker containers.
  • Hardware virtualization, with /dev/kvm, /dev/vhost-vsock and /dev/net/tun available. runed is the daemon that runs turns. It starts each turn as a KVM guest, a small virtual machine, with qemu-system-x86_64. Without /dev/kvm, runed does not start.
  • Memory for the guests. RUNED_GUEST_MEM times MAX_CONCURRENT_CONTAINERS must not exceed the memory of the host, or runed does not start. The defaults are 2 GiB and 5 guests, so they need 10 GiB.
  • Go 1.21 or newer, to build the arizuko command and the daemons. Go fetches the pinned 1.27 toolchain on the first build when the host can reach go.dev.
  • Free disk under /srv/data/ for the guest rootfs, the root filesystem of a guest. One rootfs tree is about 7 GB. sudo arizuko images <name> --prune removes the trees the instance does not use.
  • A key for the model provider, for example an Anthropic API key, and a token for one chat platform. arizuko is free. The model provider bills the usage.
  • A public domain and a TLS certificate for HTTPS, only for web chat, OAuth login or inbound webhooks. A local instance needs neither.
  • No open ports by default. The channel adapters use the docker network. Only when WEB_PORT is set does proxyd publish that port on the host.

One block of commands installs an instance

Clone the repository. The daemon images, the guest kernel and the agent rootfs build from it. Nothing mounts the checkout at run time, because the image contains the agent code from ant/. make images and make kernel need sudo. ./arizuko runs as you.

git clone https://github.com/kronael/arizuko && cd arizuko
make build                                        # ./arizuko + daemon binaries
sudo make images DATA_DIR=/srv/data/arizuko_demo  # daemon images + the guest rootfs
sudo make kernel DATA_DIR=/srv/data/arizuko_demo  # the guest kernel, built once
./arizuko create demo                             # /srv/data/arizuko_demo + .env
./arizuko packages demo add extenddb              # the store server, two passwords
./arizuko generate demo
cd /srv/data/arizuko_demo
set -a; . ./.env; set +a                          # load the STORE_* values into this shell
sudo docker compose up -d extenddb_db
sudo docker compose run --rm extenddb init \
  --pg-host extenddb_db --pg-port 5432 \
  --pg-user arizuko_demo --pg-pass "$STORE_DB_PASSWORD" \
  --extenddb-user arizuko_demo_app --extenddb-pass "$STORE_APP_PASSWORD" \
  --bind-addr 0.0.0.0 --tls-san extenddb \
  --config /var/lib/extenddb/extenddb.toml
vim .env    # STORE_ADMIN_PASSWORD and STORE_ACCOUNT_ID, which init prints once;
            # ASSISTANT_NAME, a model key, a bot token, RUNED_KERNEL_DIR, RUNED_ROOTFS_DIR
set -a; . ./.env; set +a                          # load the STORE_* values into this shell
sudo docker compose up -d extenddb
sudo docker exec -e EXTENDDB_PASSWORD=$STORE_ADMIN_PASSWORD arizuko_extenddb_demo \
  extenddb settings -c /var/lib/extenddb/extenddb.toml set control_plane_delay_seconds 0
echo "STORE_CA=$(sudo base64 -w0 store/extenddb/.extenddb/tls/cert.pem)" | sudo tee -a .env
echo 'DYNAMODB_URL=https://extenddb:18443' | sudo tee -a .env
# one store key per daemon: INSTALL.md § The per-daemon store keys
cd -
./arizuko packages demo add teled                 # one channel adapter
./arizuko group demo add telegram:group/123456789 main
./arizuko run demo                                # generate compose, docker compose up

The commands from packages demo add extenddb to the DYNAMODB_URL line set up the store server, the database that holds every row. The command packages demo add teled adds the Telegram adapter. The command group demo add telegram:group/123456789 main sends the messages of one Telegram chat to the folder main. The text telegram:group/123456789 is the address of that chat, called a JID. Replace the number with the id of your chat.

go install github.com/kronael/arizuko/cmd/arizuko@latest installs only the CLI. A full deploy still needs the repository for the images.

make images is the longest step, several minutes on the first run. It builds the daemon images and arizuko-ant:latest, the agent image. Then it exports the guest rootfs into DATA_DIR. make kernel builds the guest kernel once. Without DATA_DIR, make kernel does not start, and make images builds every image and then fails at the rootfs export. arizuko run writes a Docker Compose file and starts the stack. Docker Compose is the deploy path. For Kubernetes, read Kubernetes.

The instance is one directory under /srv/data

Pick a short name. The name becomes the data directory and the systemd unit name. ./arizuko create demo makes /srv/data/arizuko_demo/ with these entries:

.env
The instance configuration, with a new AUTH_SECRET and SECRETS_KEY. The file mode is 0600. Add API keys here later.
store/
Empty until the store server runs. Then it holds the server configuration and certificate under store/extenddb/ and the PostgreSQL data under store/extenddb_db/. One copy of the data directory therefore holds every row. Each daemon writes its own rows at its first start: routd writes the starting grants, the starting list of allowed hosts and the default group main.
groups/main/
The home of the first agent, with .claude/ and logs/. A product adds its files here, for example PERSONA.md and facts/.
web/pub/main/ and web/priv/main/
The public and the private web folder of the group. A group with the web:publish grant sees them as ~/public_html and ~/private_html.
services/ and surrogate/
The installed compose fragments and your own OAuth provider files.

Add --product <name>, for example --product personal, to copy a product into groups/main/. The command then prints the API keys that the product needs. The products section lists the catalog.

Every daemon keeps its tables on one store server

The store server is ExtendDB over PostgreSQL. It speaks the DynamoDB protocol. Every daemon reads its address from DYNAMODB_URL and does not start without it. The extenddb package adds both containers. You run the init of the server yourself, because it prints an admin password and the account id only once. Write them into .env as STORE_ADMIN_PASSWORD and STORE_ACCOUNT_ID immediately.

Each daemon signs in to the server with its own access key in env/<daemon>.env. A policy limits each key to the tables of that daemon. You make these keys by hand with extenddb manage, one for each daemon. [INSTALL.md] § The per-daemon store keys lists the daemons and the commands. A daemon without a key stops at start, and the instance then restarts in a loop. arizuko generate logs store enrolment is partial with the names of the daemons that have no key. Read that line before you continue.

arizuko run starts the stack in the foreground

arizuko run writes docker-compose.yml from the instance state and runs docker compose up in the foreground. extenddb, authd, routd, runed and timed start. onbod starts when ONBOARDING_ENABLED=true, and the web layer starts when WEB_PORT is set. In a second shell, check the status:

./arizuko status demo

For production, run the instance as the systemd service arizuko_demo. [INSTALL.md] § systemd keeps the instance running has the unit file. The logs are then in journalctl -u arizuko_demo. When the Docker log driver is none, docker logs shows nothing, so read the journal.

A channel adapter brings messages in

An instance without a channel adapter receives no messages. Pick one platform to start. Each guide shows the app or bot setup on the platform, the variables for .env, and the arizuko group add command that connects a chat to a folder.

  • Slack: a Slack app, the signing secret and the Events API.
  • Discord: a bot token, mention-only channels and threads.
  • Asymmetric channels: messages come in on one platform, and replies go out on another.

The repository has an adapter package for Telegram, WhatsApp, Slack, Discord, Bluesky, Reddit, email, X, LinkedIn and GitHub. Each daemon directory holds a README.md with its setup, for example teled/ or whapd/.

An invite link gives a user a folder

Make a one-time invite link. The target glob, a pattern with wildcards, sets the folders that the new user gets. main/** means the main group and every group under it.

./arizuko invite demo create 'main/**' --max-uses 1 --expires 24h

The command prints a token. Send https://<your-host>/invite/<token> to the user. The user signs in with an OAuth provider, such as GitHub or Google, and confirms on the next page. onbod then grants the user the admin role on the target folder. arizuko invite demo list shows the invites with a reference for each. arizuko invite demo revoke <ref> cancels one. The invite path needs ONBOARDING_ENABLED=true and a set WEB_PORT, because the link opens in a browser through proxyd.

Two checks show that the agent answers

From the host, send a message and wait for the reply:

./arizuko send demo main "ping" --wait

From the channel, send a message in the connected chat and look for it in the log of routd:

sudo journalctl -u arizuko_demo --since "2 min ago" --no-pager | grep -iE 'mention|spawn|reply'

These log lines show a problem:

this host cannot run turns
A condition of the substrate is missing. The message names each one. reference/env § runed lists the full set.
guest did not open ctl within
The guest started and never connected back to runed.
staging tree: mount source
The turn mounts a path that runed itself cannot open.
circuit breaker open
One folder failed too many turns in sequence.

Operate lists each incident with its log line, its cause and its fix.

A manifest backs up the configuration and an archive backs up everything

The configuration of an instance is data. Export it to one YAML manifest, keep the manifest in git, and apply it again to rebuild the configuration on this host or on another host.

arizuko export demo > demo.yaml   # groups, routes, grants, ACL, web routes, schedules
git add demo.yaml && git commit -m "demo config"
arizuko plan demo demo.yaml         # dry run: what would change
arizuko apply demo demo.yaml        # apply the manifest

If you apply a manifest to an empty store and export again, you get the same manifest. resreg/engine_test.go tests this. The manifest leaves out secret values, route tokens, invites, message history and the files of the agents. arizuko archive export demo writes one tar that holds all of them. The files of an agent are plain files under groups/<folder>/: the persona, the memory, the skills and the diary.

Eight terms recur in these guides

group
A workspace with files, a diary, skills and one agent. Its folder name is, for example, main or corp/eng/sre.
agent
The Claude Code process of a group. It runs in its own KVM guest, one guest for each turn. The guest starts on demand and stops when the turn ends.
turn
One run of an agent. A KVM guest starts, answers the new messages, and powers off.
channel
The place where messages come in and go out: Slack, Discord, Telegram, web or email. Each adapter is a separate daemon.
skill
A Markdown file under groups/<folder>/.claude/skills/ that the agent loads at start. One skill gives one capability.
grant
A row that lets one person or agent do one action on a set of folders. Read grants.
JID
The address of a chat, for example telegram:group/123456789. The part before : names the platform.
route token
A credential in a URL that points to a group. /chat/<token>/ opens the guest chat page. /hook/<token> accepts webhooks. /slink/<token> answers with a 308 redirect to /chat/<token>/. Read route tokens.

Audit mode stops outbound messages

Two variables on routd mute a group or a platform. The agent still runs turns, and every outbound row goes into messages. No message reaches the channel.

SEND_DISABLED_GROUPS
A comma-separated list of folder names. Example: SEND_DISABLED_GROUPS=atlas,research.
SEND_DISABLED_CHANNELS
A comma-separated list of platform prefixes, the part of a JID before :. Example: SEND_DISABLED_CHANNELS=discord.

Inbound messages do not change. The agent does not know about the mute, because reply and send return success. You see the rows at /dash/activity/ and through the inspect_messages MCP tool. Sources: routd/server.go for the group mute, routd/deliver.go for the channel mute.
