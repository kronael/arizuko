CLI

The subcommands of the arizuko binary, grouped by concern. Each entry shows the signature, the flags, the state that the command changes, and the source file. The dispatch map is in cmd/arizuko/main.go. The last section names the subcommands that this page does not describe.

The CLI uses the standard Go flag package and a small positional dispatcher. The first argument is the command. Every command except talk and probe takes -i/--instance NAME anywhere before --; without it the command uses the configured default instance. The short letters mean the same in every command: -i instance, -g group folder, -f force, -t token, -p product. -s is the scope of a token. -h/--help prints the usage of a command to stdout and exits 0. A few flags have no short form: --thread and --prompt of talk, and --seq of route add. <instance> is the suffix of the data directory: $ARIZUKO_DATA_DIR/arizuko_<name>, else ${PREFIX:-/srv}/data/arizuko_<name> (main.go).

Instance lifecycle

arizuko create [-i NAME] [-p|--product <product>]

Seed an instance data dir: write .env with a generated AUTH_SECRET and SECRETS_KEY, make services/, surrogate/ and store/, and set up the default group's folder. It writes files and no row — there is no store server yet. If --product is given, it reads ant/examples/<product>/arizuko.yml, writes the choice to .env as ARIZUKO_DEFAULT_PRODUCT, prints the env checklist. It copies no workspace file. At its first boot routd writes the main group row with that product and one installed_packages row for main; the next arizuko package sync installs the files.

FlagTypeDefaultEffect
-p, --productstring""Product template name; looked up under $HostAppDir/ant/examples/<product>/arizuko.yml. On miss, prints known products and exits non-zero.

State touched: creates ${PREFIX:-/srv}/data/arizuko_<name>/, writes .env (mode 0600), makes the services/, surrogate/ and store/ dirs, calls container.SetupGroup for the main folder skeleton. No row: routd seeds the ACL floor and the main group row at its first boot. Idempotent on .env (only written when missing).

arizuko create -i solo
arizuko create -i launch --product strategy

Config manifests

These commands read and compare cold-tier resources as YAML. They never select packages: the package commands do that, and the packages reference explains the package definition.

arizuko export [-i NAME] [output.yml]

Export cold-tier resources as YAML. Without a filename, the command writes to stdout. Each document includes a checksum of its source rows.

Show resource changes without writing to the store.

Export one resource from the live store as YAML. Secret values do not leave the store.

Full-instance backup

A config manifest carries what an instance is set up to do. An archive carries the instance: the same config, plus the encrypted secret values, the whole message history, the people still waiting to be let in, and every group's files — one tar you can move to another machine. authd’s and runed’s stores stay out: signing keys, login sessions and run records belong to the machine.

One thing deliberately stays behind: SECRETS_KEY. The encrypted secrets travel, the key that opens them does not — you carry that yourself, out of band. Restoring onto a machine whose key cannot decrypt them fails loudly instead of importing rubbish.

arizuko archive [-i NAME] export [out.tar] [--quiesced]

Write the archive. Taken from a running instance it is a smear, not a snapshot: each part is read consistently, but a message can land between two reads, so the whole is a few seconds wide rather than one instant. That is usually fine, and the archive records which it is so a restore is never guessing. Stop the instance first and pass --quiesced when you need a true point-in-time image — the flag only stamps the label; it does not stop anything for you.

State touched: read-only.

arizuko archive -i demo export demo-backup.tar
arizuko archive -i demo export demo-backup.tar --quiesced

Source: cmd/arizuko/archive.go

arizuko archive [-i NAME] apply <archive.tar> [-f|--force] [--stopped]

Restore. Config goes in first, so every group exists before its files arrive; then message history is appended (re-running the same archive changes nothing already there); then each group's files are unpacked.

Unpacking a group's files while an agent is writing them would corrupt both, so the restore takes that folder's run slot first — the same slot an agent turn takes, so the two can never overlap. This means the instance must be up and runed reachable, or you pass --stopped to say it is down. An unreachable runed is a hard stop, never a warning: proceeding is the exact accident the slot exists to prevent.

Three parts hold credentials — chat links, invites, and pending setup links. They stay out by default, and even with --force go in only when the target has none of their own. Otherwise a restore would quietly re-activate a link someone had revoked, which is still sitting in a chat somewhere. A group whose files already exist is skipped for the same reason unless you pass --force; whatever was skipped is listed in the report.

FlagTypeDefaultEffect
-f, --forceboolfalseOverwrite a group's existing files, and restore the credential-bearing parts onto an empty target. One flag for "yes, I mean it", not one per hazard.
--stoppedboolfalseYou assert the instance is down, so no run slot is claimed. Use this when restoring onto a machine where nothing is running.

State touched: writes config, message history, secret values, onboarding admissions, and groups/<folder>/ trees.

arizuko archive -i demo apply demo-backup.tar --stopped
arizuko archive -i demo apply demo-backup.tar --force

Source: cmd/arizuko/archive.go

Packages

Three subcommands manage packages. Each selection is a row in the installed_packages resource. The arizuko.yml file in a package source defines that package and selects nothing. The package reference defines sources, standard assets, order, host builds and resource ownership.

arizuko package [-i NAME] add [-g|--group <folder>] [-f|--force] <source>

Install one package and record its selection. The source is catalog:<name>, a local directory or a Git source; a relative path resolves under HOST_APP_DIR. Without -g the selection covers the whole instance. With -g it covers that group only, and the group must exist. The command creates the resource rows and services that the package declares.

FlagTypeDefaultEffect
-g, --groupstring""Group folder of the selection. Empty selects for the instance.
-f, --forceboolfalseReplace a destination that no package owns. Without it, the command stops and names the file.

State touched: one installed_packages row, the package directory under <data-dir>/packages/, service files, package-owned rows, the group/ files of the group and docker-compose.yml.

arizuko package add -i demo catalog:teled
arizuko package add -i demo -g support ant/examples/support

Source: cmd/arizuko/sync.go

arizuko package [-i NAME] rm [-g|--group <folder>] <name>

Withdraw one selection with the rows and services that the package owns. Name the package by its name, not by its source. The core package cannot be withdrawn.

State touched: the installed_packages row, package-owned rows, service files and docker-compose.yml.

arizuko package rm -i demo teled

Source: cmd/arizuko/sync.go

arizuko package [-i NAME] sync

Install every selected package again from its source. The order is core first, then the order of add. A later package overrides an earlier one on the same skill, hook, bin/ or group/ path, and the command prints one line for each override. It rewrites each group/ file from the winning package. Restart services through the deployment procedure.

State touched: the same as package add, for every selection.

arizuko package sync -i demo
demo: kronael-tools overrides core on skills/diary

Source: cmd/arizuko/sync.go

Prereqs: instance running (socket exists), claude and socat on $PATH.

arizuko chat -i demo
arizuko chat -i team -g team/discord

Source: cmd/arizuko/main.go

arizuko send [-i NAME] <folder> [<message>] [-w|--wait | -S|--stream] [--stdin] [--from <sender>] [-t|--token <raw>] [-T|--topic <t>]

Put a message into the chat of a group as web:<folder>, and optionally wait until the turn of the agent ends. By default, the command writes the message directly into the store. With --token or $ARIZUKO_CHAT_TOKEN, it posts to the /chat/<token>/ endpoint at WEB_HOST instead; the scheme is http for localhost and 127.0.0.1, otherwise https. The store keeps no raw tokens, so the CLI cannot look one up. See the tokens reference for the token model.

FlagTypeDefaultEffect
-w, --waitboolfalseAfter POST, poll /chat/<token>/<turn_id>?after=<seq> at 1s cadence, print frames, exit 0 on success / 1 on failed.
-S, --streamboolfalseSame as --wait but subscribes to /chat/<token>/<turn-id>/sse instead of polling. Exit codes: 0 success, 1 failed, 2 transport error.
--stdinboolfalseRead message body from stdin (trimmed) instead of the positional arg.
--fromstringoperatorSender of the message.
-t, --tokenstring$ARIZUKO_CHAT_TOKENRaw route token; sends through the /chat/<token>/ endpoint.
-T, --topicstringauto-genConversation thread id. Reuse the same value across calls to keep the agent in the same context.

State touched: one inbound message row, or one POST to the chat endpoint with --token.

arizuko send -i demo main "hello from cli"
arizuko send -i demo main "what's the status?" --stream
echo "long body" | arizuko send -i demo main --stdin --wait

Source: cmd/arizuko/send.go

arizuko token [-i NAME] <issue|list|revoke> ...

Manage the route tokens that back /chat/<token>/ visitor chat and /hook/<token> webhook ingest. Each token is one row in route_tokens mapping an opaque URL token to a JID and owner folder. issue mints a token for a web: or hook: JID and prints both the JID and the raw token (the token is shown once). list tabulates a folder's tokens. revoke deletes one by JID and reads the owner folder from the row. Pass <owner_folder> to name the owner explicitly. issue bearer <folder> -s|--scope s1,s2 [--ttl 1h] [--sub SUB] mints a folder-scoped ES256 access token with the active key of authd. Both issue chat and issue webhook take --context TEXT, which the agent gets as a <link-context> block.

SubcommandForm
issue chatarizuko token [-i NAME] issue chat <folder> [<suffix>]
issue webhookarizuko token [-i NAME] issue webhook <folder> <label> [<suffix>]
issue bearerarizuko token [-i NAME] issue bearer <folder> -s|--scope s1,s2 [--ttl 1h] [--sub SUB]
listarizuko token [-i NAME] list <folder>
revokearizuko token [-i NAME] revoke <jid> [<owner_folder>]

State touched: issue inserts a route_tokens row; revoke deletes one; list is read-only. issue and revoke write an audit row.

arizuko token -i demo issue chat support
arizuko token -i demo issue webhook eng github
arizuko token -i demo list support
arizuko token -i demo revoke web:support

All group verbs share the same store and dispatch under cmd/arizuko/main.go.

arizuko group [-i NAME] add <jid> <folder> [-p|--product <name>]

Create a group bound to a channel JID. Folder is validated via groupfolder.IsValidFolder. Calls container.SetupGroup for the folder skeleton seeds default tasks, inserts the group row, then adds a route room=<JidRoom(jid)> -> <folder>. For Discord guild channels (jid prefix discord: but not discord:dm/) the command writes two routes: room=<room> verb=mention at seq -1 to the folder, and room=<room> at seq 0 to <folder>#observe. So only mentions start a turn.

FlagTypeDefaultEffect
-p, --productstring""Product to select for this group (same set as arizuko create --product). The command writes one installed_packages row for the folder with the source ant/examples/<product>; the files arrive on the next arizuko package sync. On miss, errors with the expected arizuko.yml path.

State touched: filesystem (group skeleton), groups, routes, default-task seed, and with -p one installed_packages row.

arizuko group -i demo add whatsapp:120363042@g.us standup
arizuko group -i demo add discord:123456789/987654321 eng -p pm

Source: cmd/arizuko/main.go

arizuko group [-i NAME] rename <source> <destination>

Rename a folder subtree across the instance's stores and files. Use --map old=new for nested exceptions. Stop all writers and guests before execution. Produce a complete private inventory of owner tables and partition counts; the command checks the inventory against the store and owner credentials. Collisions stop preflight. Coordinate operands in ACL Params and Predicate require exact values; wildcard operands stop preflight. Ambiguous suffixed token JIDs also stop preflight. Platform chat IDs and historical text stay intact.

arizuko group -i team rename main team --map main/main=team/discord \
  --inventory /private/team-inventory.json --endpoint https://127.0.0.1:18444 --dry-run

Execution requires --stopped --yes --journal /private/team-rename. The private journal must sit outside the instance directory. Keep writers stopped through verification. To recover an interruption, repeat the original command with --resume or --rollback and the same inventory, mapping and journal. Preserve the journal and an independent store backup.

Source: cmd/arizuko/group_rename.go

arizuko group [-i NAME] rm [-f|--force] <folder>

Delete the group and every group under it with store.DeleteGroup, and sweep the rows of those folders: acl, routes, secrets, tasks and the other folder rows. A folder without a group row still has its orphan rows swept. The command first stops the live run of each removed folder at runed, using RUNED_URL and RUNED_TOKEN from the instance .env. When runed is unreachable, it removes nothing and exits non-zero. After every stop succeeds, it deletes the groups/, web/pub/ and web/priv/ directories of those folders and prints each deleted path. -f removes rows and directories without contacting runed: use it only when no run is live.

State touched: groups, the folder rows of the subtree and the three directories of each folder.

arizuko group -i demo rm standup

Source: cmd/arizuko/main.go

arizuko group [-i NAME] grant <sub> <pattern> [action] [--effect allow|deny] [--params <matcher>]

Authorize sub on a scope. The pattern ** with the default action writes acl_membership(sub, role:operator), because the operator permissions live on the role. Any other row writes acl(principal=sub, action, scope=pattern, effect, params). The action defaults to admin and the effect to allow. Valid actions: *, admin, interact, egress, web:publish, gh:write, mcp:*, mcp:<tool>, shell:env:<KEY>, ext:<provider>:<area>:<verb>, hold:mcp:<tool> and <resource>.<verb>. Idempotent. See grants reference for syntax.

State touched: acl_membership (for **) or acl table.

arizuko group -i demo grant google:alice@example.com 'solo/**'
arizuko group -i demo grant telegram:42 'corp/eng/sre'
arizuko group -i demo grant google:operator@example.com '**'   # operator role

Source: cmd/arizuko/main.go

arizuko group [-i NAME] ungrant <sub> <pattern>

Reverse of grant, with the same arguments. ** with the default action removes the operator membership edge. Any other row deletes the matching acl row.

State touched: acl_membership (for **) or acl table.

arizuko group -i demo ungrant google:alice@example.com 'solo/**'

arizuko group [-i NAME] grants [<sub>]

List grants. With no sub, it lists all grants. With a sub, it lists the grants of that subject. Columns: PRINCIPAL | ACTION | SCOPE | EFFECT | PARAMS | GRANTED_AT, then a MEMBER OF block for role memberships.

Budget (cost caps)

Per-folder and per-user daily spend caps in cents, stored on groups.cost_cap_cents_per_day and user_profiles.cost_cap_cents_per_day. The cap is arizuko’s policy; the model gateway enforces it. routd’s pre-spawn gate pushes each cap to the gateway as a one-day budget and refuses the turn when the gateway’s meter is at it. budget show prints the cap, not the spend — the spend belongs to the gateway, and reading it needs a master key this CLI does not hold; see /dash/usage/. Without a gateway nothing enforces a cap, which routd logs at ERROR. Dispatcher at budget.go.

arizuko budget [-i NAME] set <folder|user> <name|sub> -d|--daily N

Set a daily cap (in cents) on a folder or user. --daily 0 removes the cap (uncapped). Negative values are rejected.

FlagTypeDefaultEffect
-d, --dailyintrequiredDaily cap in cents. 0 = uncapped (cap row removed).

State touched: groups.cost_cap_cents_per_day (folder scope) or user_profiles.cost_cap_cents_per_day (user scope).

arizuko budget -i demo set folder corp/eng --daily 5000
arizuko budget -i demo set user google:alice@example.com --daily 1000
arizuko budget -i demo set folder solo/inbox --daily 0   # uncapped

Routes

The route table maps inbound messages to group folders. Each row is a seq (priority, lower wins), a match expression over message attributes, and a target folder. arizuko group add writes a route for you; use route to add the catch-all and cross-source rules by hand. Routes share their store with acl: both are routd's, on the instance's store server. Writes go through the audited AddRoute and DeleteRoute. Dispatcher at route.go.

arizuko route [-i NAME] list

List every route ordered by seq then id. Columns: ID | SEQ | MATCH | TARGET. An empty match renders as * (catch-all). Prints no routes if empty.

State touched: read-only.

arizuko route -i demo list

Source: cmd/arizuko/route.go

arizuko route [-i NAME] add <match> <target> [--seq N]

Add a route binding a match expression to a target folder. match is a space-separated set of key=value predicates (e.g. platform=telegram, verb=mention, chat_jid=hook:*/sentry/*); * or an empty string is the catch-all and is stored as an empty match. Prints added route <id>.

FlagTypeDefaultEffect
--seqint0Match priority; lower wins. It works before, between or after the positionals; short form -s.

arizuko route -i demo add '*' corp/intake --seq 10

Secrets (folder & user)

Folder-scoped and user-scoped secrets backing the secret-broker model (see secrets). Keys must match ^[A-Z][A-Z0-9_]*$ (validated by store.ValidSecretKey in store/secrets.go).

One table holds both scopes. Folder secrets and user secrets share the secrets table, split by scope_kind (folder or user). The same rows back the REST secret surface and the tool-call broker. Values are encrypted at rest; list shows keys, never values.

arizuko secret [-i NAME] set <folder> KEY -v|--value V

Store a folder-scoped capability secret. --value is required; empty values rejected. Key is validated against the uppercase ENV-style pattern. The five model keys (ANTHROPIC_API_KEY, ANTHROPIC_OAUTH_TOKEN, CLAUDE_CODE_OAUTH_TOKEN, OPENAI_API_KEY, CODEX_API_KEY) are rejected at folder scope — they belong to the host .env or to a user at /dash/me/env.

FlagTypeDefaultEffect
-v, --valuestring""Secret value. Required, must be non-empty.

State touched: secrets table, scope_kind = folder.

arizuko secret -i demo set corp/eng GITHUB_TOKEN --value ghp_xxxxxxxxxxxx
arizuko secret -i demo set main CF_API_TOKEN --value cf_xxxxxxxx
