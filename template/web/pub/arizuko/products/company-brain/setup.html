Company brain — setup

Design the folder tree, connect the input sources, fill facts/ and schedule the briefs. Do one team at a time.

The brain needs a public host, KVM and one channel

  • A host with Docker and a public hostname behind a TLS endpoint.
  • The build part of the install: the binary, the images and the guest kernel, with DATA_DIR set to the data directory of this instance. A turn is one KVM guest, so the host needs /dev/kvm.
  • Anthropic API access.
  • At least one channel adapter: Slack with SLACK_BOT_TOKEN and SLACK_SIGNING_SECRET, or email through emaid, or both. Webhooks need no adapter, only a hook token.

create makes the instance

arizuko create corp
arizuko packages corp add slakd
$EDITOR /srv/data/arizuko_corp/.env
ASSISTANT_NAME=corp-brain
WEB_HOST=brain.example.com
WEB_PORT=8095
ANTHROPIC_API_KEY=sk-ant-REPLACE_ME

# Slack, the recommended main channel
SLACK_BOT_TOKEN=xoxb-REPLACE_ME
SLACK_SIGNING_SECRET=REPLACE_ME

arizuko create already wrote AUTH_SECRET and SECRETS_KEY into .env. Do not change them.

The org chart becomes the folder tree

Draw the org chart first, because it becomes the folder tree. Start with two levels at most. Add a level when a real coordination problem needs it, for example when the SRE on-call rotation needs its own diary apart from the SRE team. Do not make folders in advance. An empty folder adds nothing and needs a route.

An example for an engineering company of 40 people:

corp/           # root intake triage desk
corp/eng/       # engineering channel + PR review ingest
corp/eng/sre/   # SRE runbooks + Sentry ingest
corp/pm/        # roadmap + Linear ingest
corp/sales/     # deal notes + CRM webhook

group add makes each folder and its route

Make each group folder with arizuko group corp add <jid> <folder>. The <jid> is the source chat for the folder, and the command writes its route.

# make the folders: the JID first, then the folder
arizuko group corp add 'slack:T012ABCD/channel/C0ONCALL' corp/eng/sre/oncall
arizuko group corp add 'slack:T012ABCD/channel/C0ENG'    corp/eng
arizuko group corp add 'slack:T012ABCD/channel/C0PM'     corp/pm
arizuko group corp add 'slack:T012ABCD/channel/C0SALES'  corp/sales
arizuko group corp add 'web:corp/intake'                 corp/intake

Then add the catch-all. An empty match matches every message, so every message that no other route takes goes to the intake folder. The hook routes come later, when the tokens exist:

arizuko route corp add '' corp/intake --seq 10

For many changes at once, declare the same rows in a YAML manifest and run arizuko apply corp corp-routes.yaml.

A lower seq comes first, so put specific routes before wide ones. The catch-all at corp/intake takes every message that no narrower route matches. That helps with new webhook sources before you route them.

facts/ holds the knowledge of each team

facts/ is the knowledge base of the team. The agent reads it on every relevant turn. Start with what the team uses: runbooks, decision logs and reference documents. Do not copy everything: short, current files are better than a large amount of old text.

On disk
Write Markdown files under /srv/data/arizuko_corp/groups/corp/eng/sre/facts/. This is fast for the first fill.
WebDAV
Mount https://brain.example.com/dav/corp/eng/sre/ with rclone and edit the files as a normal file system. The agent sees the changes at once.
Agent writes after a webhook
Connect a GitHub merge webhook to corp/eng/review. The agent reads the diff and the description of the pull request and writes a summary to facts/decisions/<YYYY-MM-DD>-<pr>.md. The knowledge base grows with the work, with no separate documentation task.

Each webhook source gets a token and a route

Make a hook token for each external source, then route the JID of the token, hook:<folder>/<label>, to the folder that handles it:

# Sentry alerts
arizuko token corp issue webhook corp/eng/sre/oncall sentry
# webhook URL: https://brain.example.com/hook/<token>
# paste it into Sentry: Organization Settings → Integrations → Webhooks
arizuko route corp add 'chat_jid=hook:corp/eng/sre/oncall/sentry' corp/eng/sre/oncall --seq -10

# GitHub
arizuko token corp issue webhook corp/eng github
# paste it into the GitHub repository → Settings → Webhooks
arizuko route corp add 'chat_jid=hook:corp/eng/github' corp/eng --seq -5

The body arrives unchanged in the target folder, and a skill of the agent parses it. Webhooks explains signature checks and the security model.

Scheduled tasks write the briefs

A scheduled task starts a turn in a folder on a cron schedule, with no host cron and no systemd timer. The scheduler, timed, is part of the stack. No CLI subcommand for tasks exists. Add tasks on the tasks page of /dash/, declare scheduled_tasks rows in a manifest for arizuko apply, or ask the agent:

@corp-brain schedule a recurring task:
  folder: corp/eng   cron: "0 9 * * 1-5"
  task: write daily standup summary to facts/briefs/today.md and send to #eng-standup

The agent writes the task row with the schedule_task MCP tool, and timed sends the prompt on schedule. Examples:

foldercadence (cron)task
corp/eng0 9 * * 1-5write daily standup summary to facts/briefs/today.md and send to #eng-standup
corp/pm0 8 * * 1write weekly roadmap digest to facts/briefs/week.md and send to #pm-digest
corp/eng/sre0 18 * * 5write on-call handoff brief and send to #eng-oncall

Make each task instruction specific: what to produce, where to write it and where to send it.

arizuko run starts the instance

arizuko run corp

For production, run the instance as a systemd service, as getting started shows.

Four checks show that the brain works

  • Send a test Sentry webhook to the hook URL. Run sudo journalctl -u arizuko_corp | grep 'hook inbound' and find the line.
  • Post a message in the connected Slack channel. The agent replies or observes, as the route says.
  • Test a brief now: ask the agent in a chat to run the brief prompt once, or set the cron of the task to the next minute on the tasks page.
  • Open the groups page of /dash/. Each folder shows with its route and its scheduled tasks.

Grants stay inside each folder

By default, the agent of each folder reads its own facts/, writes its diary and replies on its channel. Nothing crosses folders. The CLI writes grant rows. Without an action, a grant gives a person admin over a folder subtree, and '**' makes the person an operator:

arizuko group corp grant google:cto@acme.com 'corp/**'

The CLI also writes finer rows: an action such as interact or mcp:<tool>, --effect deny, and --params. The grants page of /dash/ does the same. Grants has the full rule syntax.

An observe route collects context without replies

For Slack channels where you want context but no replies, such as general chat, route to <folder>#observe. The agent stores the messages, starts no turn and sends nothing to the channel:

arizuko route corp add 'chat_jid=slack:*/channel/C0GENERAL' 'corp/eng#observe' --seq 5

The routes page of /dash/ and a YAML manifest with arizuko apply also work. When the agent in corp/eng answers a question, it can use messages from the observed channel through find_messages.

Three problems have a known cause

A webhook arrives and no turn starts
The route must match the hook JID exactly: hook:corp/eng/sre/oncall/sentry for a token of corp/eng/sre/oncall with the label sentry. Run arizuko route corp list and compare it with the JID in the hook inbound log line.
A brief runs and the agent sends nothing
The task instruction has no send step. Edit the task on the tasks page and add "send to #<channel>". Without it, the agent writes the brief to facts/ and stays silent, which is correct for that instruction.
The agent replies in the wrong folder
The route order is wrong. Run arizuko route corp list and check the seq values: the lower one comes first. Add a narrower route with a lower seq with arizuko route corp add.
