PM agent (Sloth)

Keeps the task board, writes the weekly status, and logs decisions with their context. Moves slowly, forgets nothing, and never invents scope.

Sloth keeps the board in a Markdown file

The board is facts/tasks.md, a file in the group that you can read and diff. The persona tells Sloth to update it on an explicit instruction, for example "mark X done" or "add Y, owner Z, Friday", and to confirm the owner and the deadline before it writes. It tells Sloth to flag blocked or overdue tasks. The product ships no scheduled task, so Sloth flags them in a turn that a message, or a task that you add, starts.

The persona tells Sloth to put each decision in facts/decisions/, one file for each decision, with the context that produced it.

A sample exchange

user   mark the migration task done

agent  facts/tasks.md — "0034 outbound retry migration", owner mira,
       due 2026-08-12. Mark it done as of today?

user   yes

agent  Done. Two tasks still blocked: "route token rotation" (waiting on
       mira since the 9th) and "eval budget" (no owner). Want me to ping?

The product ships four files

FileWhat it is
PRODUCT.mdthe manifest: name, brand, tagline and env hints
SOUL.mdwho the agent is; runed renames it to PERSONA.md at the first turn; precise, confirms before it writes
facts/team.mdthe team members, their roles and contacts
facts/tasks.mdthe board, with the row format and no rows

The product also ships its tests in eval/.

The persona tells Sloth never to run code or touch infrastructure. Sloth tracks the work, and other agents do the work.
