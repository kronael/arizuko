Personal assistant setup

The personal assistant needs one Telegram bot and a preferences file with what it must know about you.

The assistant needs an instance and a Telegram bot

  • A running instance, from getting started.
  • TELEGRAM_BOT_TOKEN. The product declares it as required, because an assistant with no channel is only a directory.

create seeds the instance from the product

arizuko create fiu --product personal
arizuko packages fiu add teled

The first command copies the product tree into the default group. To add the product to an existing instance as one more group:

arizuko group <instance> add telegram:user/12345678 me --product personal

.env holds the token

TELEGRAM_BOT_TOKEN=REPLACE_ME
OPENAI_API_KEY=REPLACE_ME   # optional: the oracle skill

The preferences file holds what Fiu must know

facts/preferences.md makes the difference between a generic assistant and your assistant. Write what you would otherwise repeat: how you like drafts, what you work on, your timezone and the names that come up often. It is a file, so edit it when it is wrong.

Memory belongs to one folder. The diary and facts/ belong to the group, so a second group has a second memory, and nothing is shared. That is the containment guarantee, not a limit to work around. Scopes explains it.

The assistant must quote your preferences

arizuko send <instance> me "what do you know about how I like drafts?" --wait

A correct answer quotes your preferences file. A generic answer means that the file is not in place. Check groups/me/facts/preferences.md.

Three changes tune the assistant

Voice
Edit the persona file, PERSONA.md after the first turn.
What it remembers
The agent adds to facts/ itself. Remove old entries when they are wrong. Stale preferences are the main failure of a memory product.
Reminders
Ask the agent for a reminder, and it makes a scheduled task. A task is a row on the store, not a file in the folder.
