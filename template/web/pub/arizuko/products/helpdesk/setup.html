Helpdesk setup

You can make a new group from the product, or add the product to a group that you already have. Both ways put the same files in the same places.

One placement rule serves both ways, so a product means the same thing however you apply it. Only the skill moves: the product ships it at skills/<name>/, and it goes to .claude/skills/<name>/, where the agent reads it.

The product needs an instance and one channel

  • A running instance, from getting started.
  • One channel adapter, so that support messages reach the agent. Slack is the usual channel for a support queue.
  • Nothing more. The product ships no sidecar, no image extension and no external credential.

group add makes a new group with the product and its route

The Slack JID names the workspace, the kind and the channel. Send /chatid in the channel to get it.

arizuko group <instance> add slack:T012ABCD/channel/C0SUPPORT acme/support --product helpdesk
arizuko route <instance> list
ID  SEQ  MATCH                            TARGET
1   0    room=T012ABCD/channel/C0SUPPORT  acme/support

The command copies the product tree into groups/acme/support/ once. After that, the files belong to the group. Edit the persona and add facts, and nothing writes over them. group add also writes the route, so every message in that Slack channel reaches the acme/support agent.

To add a second channel, add a second group. To add a webhook or a public chat link, make a route token, as webhooks and chat link show. All of these inputs reach the same folder and the same agent.

products.toml adds the product to an existing group

A group can run several products. Write the mix into products.toml in the group and apply it:

[[product]]
source = "ant/examples/helpdesk"
arizuko products <instance> apply acme/support

A second apply of an unchanged mix writes nothing and reports unchanged. arizuko reports a file that you changed as dirty and skips it.

An escalation to an agent is a delegation

The product escalates billing and account questions. An escalation to a person is a message. An escalation to another agent is a delegation. Make the billing group first, because nothing makes it for you:

arizuko group <instance> add slack:T012ABCD/channel/C0BILLING acme/billing

The support agent then calls delegate_group with the billing folder and the request. The billing agent runs its own turn, in its own guest, with its own grants and its own egress allowlist. It is a peer, not a subroutine.

The delegating agent needs a grant. role:member does not hold delegate_group, so an operator must grant it to the support folder, with a scope that covers acme/billing. Until then, the agent says that it cannot escalate. That is the correct failure.

The billing agent can also only watch the support channel and get no tickets. Give it an observe route on the same chat:

arizuko route <instance> add 'chat_jid=slack:T012ABCD/channel/C0SUPPORT' 'acme/billing#observe' --seq 2

With #observe, the billing agent sees the messages and does not reply. Two agents read one channel, and one of them is silent. Routing has the full match and fragment grammar.

One optional variable names the escalation target

The product declares one optional variable. It is a hint: a missing value gives a warning and does not stop the apply.

HELPDESK_ESCALATION_CHANNEL=acme/billing

The facts folder holds what your team promises

facts/sla.md ships with one line, so the shape is clear. Replace it with what your team promises, and add one file for each topic, for example the refund window, the supported versions and the escalation rota. The agent answers from these files. It escalates every question that the files do not answer.

A billing question must escalate

arizuko send <instance> acme/support "I was charged twice for March, ticket 4417" --wait

A correct answer escalates, does not resolve, and quotes the ticket ID. If the agent offers a refund, the CLAUDE.md region did not arrive. Check that groups/acme/support/CLAUDE.md has an arizuko:package:helpdesk marked region.

Four files tune the agent

Voice
Edit PERSONA.md.
Rules
Edit inside the marked region of CLAUDE.md, or write your own rules outside it. arizuko does not change text outside the markers.
Triage classes
Edit .claude/skills/triage/SKILL.md. It is under .claude/ in the group, although the product ships it at skills/triage/.
A skill to turn off
Put a .disabled file in the directory of the skill.
