MacroHype — setup

Install the package, fill one config file, allow two hosts and schedule one run a day.

Select the package

arizuko package add -g FOLDER github.com/kronael/arizuko/packages/macrohype@v0.75.8

The guest needs python3 3.11 or newer. The script uses only the standard library.

Fill the config

The skill ships macrohype.example.toml. Copy it to ~/macrohype.toml in the group once, then edit it:

cp packages/macrohype/skills/macrohype/macrohype.example.toml /srv/data/arizuko_<instance>/groups/FOLDER/macrohype.toml

Set user_agent to a client name and your contact address. Wikimedia asks that of automated clients. Then set the watchlist: each asset has a name, a Bybit linear perpetual symbol and a Wikipedia article title. Set window, alert_z and calm_z. Every key is required, and the script stops when the file or a key is missing.

Allow the two sources

arizuko network allow FOLDER api.bybit.com
arizuko network allow FOLDER wikimedia.org

Neither source needs a key. A 403 Forbidden tunnel error in a Failed: line means that a rule is missing.

Schedule one run a day

Put the task row in a file and apply it. Run it after Wikimedia has published the previous day; 12:00 UTC leaves a margin.

scheduled_tasks:
  - id: macrohype-check
    owner: FOLDER
    chat_jid: CHAT_JID
    prompt: /macrohype check
    cron: 0 12 * * *
    status: active
    context_mode: isolated
arizuko apply task.yml

The series are daily. A second run on the same day requests nothing and posts nothing. A run that comes late judges each missed day in order.

Ask for the current phase

Ask the agent for the phase of an asset. It runs status, which reads the days on disk and makes no request. Before the first check, status fails and the agent says so.
