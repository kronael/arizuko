Slack team agent

One agent in a Slack channel, with channel-scoped persona and thread context but per-teammate memory, grants, and a full web workspace. Scale it up and it becomes a tree of them: each department shapes its own agent, and the agents hand work along the tree.

Each teammate gets storage, memory and grants

Personal cloud storage
Each teammate has a private workspace over WebDAV. Mount it with rclone and open it in Finder, VS Code or another file manager. Notes, uploads and agent outputs stay across sessions.
Web chat
A browser chat at /chat/<token>/ talks to the same agent. Move the conversation from Slack to a phone or a laptop and keep the context.
Google Docs and web pages
The agent reads public web pages and Google Docs that you share. Paste a URL, and the agent fetches the content. A private document must be shared by link, because the agent has no OAuth access to your Google account.
Dashboard
Operators and teammates with dashboard access see the activity, the grants, the routes and the scheduled tasks at /dash/. Operators also see the usage at /dash/usage/.
Per-teammate memory
The agent keeps one memory file for each teammate, with preferences, recurring tasks and earlier conclusions. Alice has hers, and Bob has his.
Per-teammate grants
Grant rows decide which actions each teammate can ask the agent to do. Operators set the defaults, and each person can have own rows.
Linked identities
The channel needs no sign-in, because membership of the workspace is the fence. A teammate who signs in at /auth/login with GitHub, Google or Discord links that identity to the Slack user. The same person then reaches the same memory and grants from the web chat, a DM or another channel.

A Slack channel is a group folder

Channel as workspace
A Slack channel maps to an arizuko group folder. The product puts its persona and its rules into the CLAUDE.md of the group, inside a marked region. The channel adds its own rules outside the region: allowed tools, citation rules, refusals and the voice for this channel. So #eng-support acts differently from #design and #incidents. The folder is available over WebDAV at /dav/<folder>/.
Per-user memory
The users skill keeps one file for each sender in users/ in the channel folder, for example users/tg-123456.md. The prompt names the file of the sender. Per-user secrets are different: they live at /dash/me/secrets, and the broker on the host gives them to tools.
Per-user grants
Grant rows for each user decide which actions that user can ask the agent to do. A child folder such as eng/alice/ has its own files. It copies nothing from the parent folder.
Changes stay in place
The persona, the skills and the channel rules are Markdown files that you edit over WebDAV or in the chat. A release that changes the platform skills increases MIGRATION_VERSION, and each group runs one /migrate turn to update itself.

One workspace can hold an agent for each department

The setup for one channel grows to a whole organisation with no new parts. Folders nest, for example acme/eng, acme/sales and acme/support, and each Slack channel routes to the folder of its department. Each department then shapes its own agent: its persona, its skills and its knowledge, edited by the people who own that work. Eng changes the agent of eng, and sales sees no change.

The agents reach each other through the tree. A department agent that gets a question outside its work escalates to the parent. The parent can delegate work to another child. The platform checks the grant of each step and allows one level of delegation, and the answer comes back in the chat of the question.

#sales · routed to acme/sales

  dana   @bot can we promise SSO for the Klein deal by Q3?
  bot    Outside my lane — asking up the tree.
         [sales escalates to acme; acme delegates to acme/eng]
  bot    From eng: OIDC lands mid-Q3, SAML is still in review.
         Safe to promise OIDC-based SSO; caveat SAML.

People move as easily as the work. Type @eng alone in a chat, and the chat talks to the eng agent. Type @sales, and the chat goes back. Each department keeps its files, memory and secrets in its own folder. An agent that fails or acts wrongly in one folder reaches nothing in another folder.

A shared thread keeps per-user state apart

#eng-support · thread

  alice  @bot summarize the fix from the cold-start runbook for this thread
  bot    Bundle growth after deploy is coming from broad SDK imports.
         Recommended: switch back to per-service imports.
         source: /docs/runbooks/lambda-cold-start.md:67

  bob    @bot save that conclusion to my notes
  bot    Wrote notes/lambda-cold-start.md in your user area.

  alice  @bot remember: prefer per-service imports for any new lambda
  bot    Saved to your memory.

The thread and the channel CLAUDE.md are the same, and the user state is different. The team sees the answer. The write of Bob goes to the user area of Bob, and the preference of Alice goes to her memory file. Alice cannot see the notes of Bob, and the memory of neither user goes into the shared context of the channel.

Teammates use the pane, channels, threads and DMs

AI pane
Click the AI icon in Slack to open a private pane with the channel agent: suggested-prompt buttons, a title for each pane, and the channel context. Slack pane has the details.
In a channel
The bot is quiet by default. A mention of the bot starts a turn. With the route from the setup guide, the other messages go to #observe: the agent reads them as context and replies only when someone calls it.
In a thread
A reply to a bot message counts as a mention. The agent answers in the same thread, with the history of the thread as context.
In a DM
Every message is for the bot, so no mention is necessary. Replies come back in the same DM.
File uploads
Send a file to the bot or put it in a thread with a mention. The agent reads the file and replies in the thread.
Reactions
A reaction on a bot message arrives as verb=like or verb=dislike. A route that matches the verb starts a turn, for example for a "thumbs up to confirm" flow.

Three uses share the same product

A support agent answers from a knowledge base

The agent answers questions from a knowledge base, cites the sources and escalates when it does not know. It fits internal help desks, customer support channels and questions about documentation.

  • Searches a facts/ directory of Markdown files for answers.
  • Cites the source file and the line number.
  • Says "I don't know" and does not guess.
  • Can sort and tag issues and track their status.
  • Escalates to a person when it cannot answer or when the user asks.
#eng-support

  user   How do I reset my API key?
  bot    To reset your API key:
         1. Go to Settings → API Keys
         2. Click "Regenerate" next to the key you want to reset
         3. Copy the new key immediately — it won't be shown again
         source: docs/api-keys.md:45

  user   What about enterprise SSO setup?
  bot    I don't have documentation on enterprise SSO in my knowledge base.
         I've flagged this for the team. Someone will follow up.

A research agent collects market observations

A shared research agent reads news, tracks market data and writes analysis. It works best when several teammates add observations and the agent combines them.

  • Fetches and summarises news from URLs that you paste.
  • Records the observations of teammates over time.
  • Keeps a shared research diary with dated entries.
  • Compares several sources to find patterns.
  • Writes a summary report on request.
#market-watch

  alice  https://example.com/article-about-earnings
  bot    Summarized: Q2 earnings beat estimates by 12%. Key drivers:
         cloud revenue +34% YoY, hardware flat. Guidance raised for Q3.
         Logged to research diary.

  bob    I noticed unusual options activity on XYZ today
  bot    Noted. Adding to today's observations. You've logged 3 observations
         this week on XYZ — want me to compile a summary?

  alice  Yes, give us the weekly synthesis
  bot    Weekly synthesis for XYZ:
         - Monday: Earnings beat, guidance raised (source: earnings article)
         - Wednesday: Insider filing showed CEO sold 10k shares
         - Today: Unusual options activity (Bob's observation)
         Pattern: Mixed signals. Fundamentals strong but insider selling
         and options activity suggest caution.

A general team assistant

The default setup: questions and answers, summaries, file processing and task tracking for a team channel.

Your data stays on your server

Your server
The channel files, the per-user memory and the agent state are files under /srv/data/arizuko_<name>/groups/. The conversation history and the secrets are on the store server of the instance.
Outbound paths
Slack for the bot, Anthropic for model calls. Other traffic of the agent goes through egress and reaches only the hosts that you allow for each channel.
Channel secrets
The API keys of the tools live in the secrets table, encrypted with AES-256-GCM under SECRETS_KEY. They never enter the guest. The broker on the host reads the key for each tool call, uses it in the outbound request and removes it from the result.
Channel boundary
A teammate in #eng-support sees the context of that channel and the own user area. The files and the persona of #design stay closed without an explicit grant.

The same shape works on Discord

Most of this page applies to Discord. Server channels act like Slack channels, with a JID for each room, a CLAUDE.md for each channel and per-user memory. Threads act like Slack threads. Three things differ:

No AI pane
Discord has no assistant pane like Slack, and discd shows no suggested prompts. DMs and mentions work the same.
Different mentions
Slack writes <@USERID> in the text, and Discord writes <@123456789>. The adapters replace both with @<assistant-name> before the agent sees the message.
Different JIDs
Slack: slack:T1234/channel/C5678. Discord: discord:<guild_id>/<channel_id>. The grants are the same.

To run the product on both platforms, install both adapters and route each channel to the same folder. The agent does not see a difference.

Five commands set it up

arizuko create acme --product slack-team
arizuko packages acme add slakd
$EDITOR /srv/data/arizuko_acme/.env    # SLACK_BOT_TOKEN, SLACK_SIGNING_SECRET, ANTHROPIC_API_KEY
arizuko group acme add slack:T012ABCD/channel/C0ENGSUP main
arizuko run acme

# in Slack:
#   make the Slack app; put the bot token and signing secret in .env
#   point the events at https://<your-host>/slack/events
#   invite the bot to a channel; teammates sign in at /auth/login

The operator setup guide has every step. The Slack how-to covers the Slack details. The CLAUDE.md of each channel is in the channel folder. Edit it over WebDAV or on the server.
