Taxonomy chat (Marble) — setup

Take an open dataset, put it into a folder, add a public chat link and run it on a small model. This guide uses the Marble Skill Taxonomy, and the same shape fits any JSON dataset that an agent can query with jq.

The bot needs a public host and a JSON dataset

  • A running arizuko instance with a public hostname, WEB_HOST. Read getting started.
  • Anthropic API access. No web search is necessary, because the dataset is in the folder.
  • A dataset as one or more JSON files. Here: topics.json, dependencies.json and clusters.json from the Marble Skill Taxonomy.

group add makes the public group and its route

Add a folder for the bot and a route that sends its web chat JID to it. arizuko group add writes the group row, makes the folder and adds the route in one step:

arizuko group <instance> add web:<folder> <folder>

# example: a public child folder under an existing world
arizuko group krons add web:krons/public/marble krons/public/marble
The CLI finds the data directory from the instance name. It uses /srv/data/arizuko_<instance>. ARIZUKO_DATA_DIR replaces /srv/data, and PREFIX replaces /srv. The agent can also make the child group itself with register_group, when its folder holds that grant.

The dataset goes into the group folder

Put the JSON into the group folder. The agent reads it from ~/taxonomy/ in its guest, which is groups/<folder>/taxonomy/ on the host:

mkdir -p /srv/data/arizuko_<instance>/groups/<folder>/taxonomy
cp topics.json dependencies.json clusters.json \
   /srv/data/arizuko_<instance>/groups/<folder>/taxonomy/

The files must have the same owner as the rest of groups/. The dataset is read-only reference data: the agent queries it and never writes it.

CLAUDE.md holds the instructions

The CLAUDE.md in the group folder holds the instructions of the agent: who it is, what it answers and how it cites. Keep it short, because the agent reads every line at each turn.

cat > /srv/data/arizuko_<instance>/groups/<folder>/CLAUDE.md <<'EOF'
# Marble Taxonomy Chat

I am the "Talk to the Taxonomy" assistant - a public web chat over the
Marble Skill Taxonomy v1.

## What I do

I answer questions about what children learn and in what order by
searching `~/taxonomy/*.json`. I trace prerequisite chains, list what a
topic unlocks, filter by subject/age, keep answers tight, and cite topic
names.

## Data

Data (c) Marble (withmarble.com), CC BY-SA 4.0.

## Running

I run on a small model and reply concisely and friendly to visitors via
the web chat widget.
EOF

The identity is in CLAUDE.md, and the product has no PERSONA.md. Add one only for a separate voice on top of the instructions.

The group runs on Haiku

A public lookup bot does not need a large model. Set it to Haiku in the group settings: /dash/groups/<folder>/settings → Model → Claude Haiku 4.5. The setting writes the model into the config of the group, and runed gives it to the guest as ARIZUKO_MODEL at the next turn.

The same change without the dashboard writes the same JSON through the groups resource:

arizuko get <instance> groups > groups.yaml
# in groups.yaml, on the row of the folder:
#   config: '{"model":"claude-haiku-4-5-20251001"}'
arizuko apply <instance> groups.yaml

Fewer skills make each turn faster

Each turn starts a new guest with no prompt cache, so the system prompt lists every seeded skill again at each answer. A read-only taxonomy bot needs almost none of the stock skills. At /dash/groups/<folder>/settings, keep self, migrate and hello, and turn off the rest. The prompt is then smaller, and turns are faster.

A marker file turns a skill off. The dashboard writes a .disabled file in the directory of each skill that you turn off, under groups/<folder>/.claude/skills/. At the next spawn, seedSkills removes the SKILL.md of that skill, so Claude Code does not index it. To turn the skill on again, remove the marker. Auto-migrate still works, because it uses the MIGRATION_VERSION file and the migrate skill, which do not depend on the markers.

A chat token makes the public link

arizuko token <instance> issue chat <folder>
# prints the token; the chat URL is https://<WEB_HOST>/chat/<token>/

That URL is the only entrance. Open it in a browser and ask a question, or put the chat into any page with the chat SDK. No adapter and no login are necessary.

A question in the chat must get a reply

  • curl -sI https://<WEB_HOST>/chat/<token>/ | head -1 returns 200.
  • Ask a question in the chat. A reply arrives in a few seconds.
  • Check that the model setting applies: /dash/groups/<folder>/settings shows Haiku.
  • Look for errors: sudo journalctl -u arizuko_<instance> --since "5 min ago" | grep -iE 'error|fatal'.

Four changes tune the bot

Answer length and citations
Edit the CLAUDE.md of the group. A public bot needs short answers with citations, so write that into the file.
Latency
The two largest costs are the start of a new guest and the number of jq calls for each answer. The model and the skill steps make the model and the prompt smaller. To make fewer calls, prepare the dataset with a summary file or precomputed indices, so common questions need one or two calls instead of ten.
Load limit
Each visitor question is one guest, so the instance-wide MAX_CONCURRENT_CONTAINERS limits the load.
Another dataset
Nothing here is specific to Marble. Replace taxonomy/*.json with any dataset, describe it in CLAUDE.md, and the same bot answers over your data.
