Discord team agent

This is a shape, not a template. No tree ships for it in ant/examples/, so there is no --product discord-team to run. The page describes how the product is assembled from the primitives; every command below is one you run yourself. The catalog marks which products ship as templates.

One agent in a Discord guild, with channel-scoped persona and thread context but per-member memory, grants, and a full web workspace.

The Discord team agent has the same folder model, grants and web workspace as the Slack team agent. That page describes the shared parts and the three uses: a support agent, a research agent and a general team assistant. The sections below list what is the same and what differs on Discord.

Each member gets storage, memory and grants

Personal cloud storage
Each member has a private workspace over WebDAV at /dav/<folder>/. Notes, uploads and agent outputs stay across sessions.
Web chat
A browser chat at /chat/<token>/ talks to the same agent, so a member can move the conversation from Discord to a phone or a laptop.
Dashboard
Operators and members with dashboard access see the activity, the grants, the routes and the scheduled tasks at /dash/.
Per-member memory and grants
The agent keeps one memory file for each member. Grant rows decide which actions each member can ask the agent to do.
Linked identities
The channel needs no sign-in, because membership of the guild is the fence. A member who signs in at /auth/login with GitHub, Google or Discord links that identity to one user, so the member reaches the same memory and grants from the web chat or a DM.

A Discord channel is a group folder

A Discord channel maps to an arizuko group folder. The CLAUDE.md of the folder holds the rules of the channel: allowed tools, citation rules, refusals and voice. A Discord thread is a topic under the JID of its parent channel. The agent sees the history of the thread as context, and replies stay in the thread.

A shared thread keeps per-member state apart

#dev-chat · thread

  alice  @bot summarize the fix from the cold-start runbook for this thread
  bot    Bundle growth after deploy is coming from broad SDK imports.
         Recommended: switch back to per-service imports.
         source: /docs/runbooks/lambda-cold-start.md:67

  bob    @bot save that conclusion to my notes
  bot    Wrote notes/lambda-cold-start.md in your workspace.

  alice  @bot remember: prefer per-service imports for any new lambda
  bot    Saved to your memory.

The thread and the channel CLAUDE.md are the same, and the member state is different. The team sees the answer. The write of Bob goes to the workspace of Bob, and the preference of Alice goes to her memory file.

Three things differ from Slack

No AI pane
Discord has no assistant pane, and discd shows no suggested prompts. Mentions and DMs work as on Slack.
Mention-only by default
arizuko group add for a Discord server channel writes two routes: a verb=mention route that starts turns, and an #observe route for the other messages. A reply to a bot message also counts as a mention.
Different JIDs
A channel is discord:<guild_id>/<channel_id>, and a DM is discord:dm/<channel_id>. The grants are the same as on Slack.

Your data stays on your server

Your server
The channel files, the member memory and the agent state are files under /srv/data/arizuko_<name>/groups/. The conversation history and the secrets are on the store server of the instance.
Outbound paths
Discord for the bot, Anthropic for model calls. Other agent traffic goes through egress and reaches only the hosts that you allow for each channel.
Channel secrets
The API keys of the tools live in the secrets table, encrypted with AES-256-GCM. They never enter the guest: the broker on the host uses each key in the outbound request and removes it from the result.
Channel boundary
A member in #dev-chat sees the context of that channel and the own workspace. The files and the persona of #marketing stay closed without an explicit grant.

Five commands set it up

arizuko create acme
arizuko packages acme add discd
$EDITOR /srv/data/arizuko_acme/.env    # DISCORD_BOT_TOKEN, a model key
arizuko group acme add discord:123456789/987654321 main
arizuko run acme

# in Discord:
#   make the bot at discord.com/developers/applications
#   invite the bot to your guild with the OAuth2 URL generator
#   members sign in at /auth/login to link identities

The operator setup guide has every step. Edit the CLAUDE.md of each channel in the channel folder, over WebDAV or on the server.
