Discord team agent — setup

The setup puts one agent into a Discord guild: an arizuko instance, a Discord bot, linked identities through OAuth, and the web workspace.

The agent needs a public host, a guild and KVM

  • A host with Docker and a public hostname behind a TLS endpoint.
  • A Discord server, a guild, where you have admin permissions.
  • The build part of the install: the binary, the images and the guest kernel, with DATA_DIR set to the data directory of this instance. A turn is one KVM guest, so the host needs /dev/kvm.
  • Anthropic API access for the agent in the guest.

create makes the instance with the generic persona

arizuko create acme
arizuko packages acme add discd
$EDITOR /srv/data/arizuko_acme/.env

No discord-team template exists, so the main group starts with the generic persona. The nearest start is ant/examples/slack-team/. Copy its PERSONA.md and CLAUDE.md into groups/main/ and remove the Slack lines, for example the AI pane and the channel words. Or write your own files.

.env holds the Discord token and the OAuth providers

# Identity + secrets
ASSISTANT_NAME=acme              # agent display name
AUTH_SECRET=REPLACE_ME           # arizuko create writes it
WEB_HOST=acme.example.com        # public hostname for proxyd and OAuth callbacks
WEB_PORT=8095                    # starts the web layer

# Discord adapter
DISCORD_BOT_TOKEN=REPLACE_ME     # from the Discord Developer Portal

# OAuth providers for linked identities, any subset
GITHUB_CLIENT_ID=REPLACE_ME
GITHUB_CLIENT_SECRET=REPLACE_ME
GOOGLE_CLIENT_ID=REPLACE_ME
GOOGLE_CLIENT_SECRET=REPLACE_ME
DISCORD_CLIENT_ID=REPLACE_ME
DISCORD_CLIENT_SECRET=REPLACE_ME

arizuko create already wrote AUTH_SECRET and SECRETS_KEY. Do not change them. reference / env lists every variable.

The Discord bot needs the Message Content Intent

In discord.com/developers/applications:

New Application
Give it a name and save it.
Bot
Click "Add Bot" and copy the token into DISCORD_BOT_TOKEN.
Privileged Gateway Intents
Enable "Message Content Intent", so that the bot can read the message text.
OAuth2 → URL Generator
Select the scope bot. Select the permissions Send Messages, Read Message History, Add Reactions and Attach Files. Copy the generated URL.
Invite
Open the URL in a browser, select your guild and authorize.

Discord has the same steps in more detail.

arizuko run starts the instance

arizuko run acme

The command writes a Docker Compose file and starts it. For production, run the instance as a systemd service, as getting started shows.

A mention in a channel must get a reply

  • arizuko status acme shows all services up and the Discord channel connected. discd connects out to the Discord gateway, so no public /discord/ URL exists to test.
  • sudo journalctl -u arizuko_acme --since "5 min ago" | grep -E "discord connected|channel registered" shows the connection and no auth errors.
  • In Discord, send @acme hello in a channel that the bot can see. The agent replies.
  • Open https://<WEB_HOST>/dash/ as the operator. The guild channel shows as a group with routes.

The usual routes answer DMs and mentions and observe the rest

A guild bot usually answers every DM and stays quiet in channels until someone mentions it. A guild channel JID is discord:<guild_id>/<channel_id>, and a DM is discord:dm/<channel_id>:

seq  match                                target
-2   chat_jid=discord:dm/*                main
-1   chat_jid=discord:*/* verb=mention    main
0    chat_jid=discord:*/*                 main#observe

The channel messages still go into main under #observe, so the agent has the context at the next mention. No turn starts until someone calls the agent. arizuko group add on a guild channel JID writes this mention and observe pair for that one channel. The rows above do the same for every guild, with arizuko route acme add <match> <target> --seq N.

A sign-in opens the member features

Channel use needs no sign-in. For the personal cloud, the web chat and one identity across platforms, members sign in at https://<WEB_HOST>/auth/login.

Personal cloud
A signed-in member can open /dav/<folder>/ in the browser. A WebDAV client needs a Bearer token, as WebDAV shows.
Web chat
The /chat/ page lets members continue a conversation in a browser.
Dashboard
Members with the grants see their folders at /dash/.

CLAUDE.md sets the use of a channel

Support agent

For a support channel, put your knowledge base into facts/:

# copy the documentation into facts/
cp /path/to/docs/*.md /srv/data/arizuko_acme/groups/main/facts/

# or point CLAUDE.md at external sources
$EDITOR /srv/data/arizuko_acme/groups/main/CLAUDE.md

Add these rules to the CLAUDE.md of the channel:

## Support behavior

When answering questions:
1. Search facts/ first with /recall-memories
2. Cite the source file and line number
3. If the answer isn't in facts/, say "I don't have that in my knowledge base"
4. Never guess or make up information
5. Offer to escalate to a human when stuck

Research agent

For a shared research channel, tell the agent to record observations and write summaries:

## Research behavior

When members share URLs:
1. Fetch and summarize the content
2. Log key points to the research diary with timestamp
3. Note which member shared it

When members share observations:
1. Acknowledge and log to diary
2. Cross-reference with recent entries
3. Offer to compile synthesis when patterns emerge

On request for synthesis:
1. Review diary entries for the requested period
2. Group by topic/ticker
3. Note patterns and contradictions
4. Cite sources for each point

Each channel folder has its own CLAUDE.md

Each Discord channel maps to a group folder. To change the voice, the allowed tools or the skills of one channel, edit its CLAUDE.md, over WebDAV at https://<WEB_HOST>/dav/<folder>/CLAUDE.md or on disk.

Secrets for one channel stay in that channel. Put the API keys of tools that one channel needs into the secrets table: arizuko secret <instance> set <folder> KEY --value V.

Each new channel is one more group

Map a new channel to a folder, with the guild ID first and then the channel ID:

arizuko group acme add 'discord:123456789/987654321' dev-chat

For a guild channel, the command also writes the mention route and the observe route. For a persona or a skill set for this channel, edit CLAUDE.md in the new folder.

Four problems have a known cause

The bot does not answer
Check that "Message Content Intent" is on in the Discord Developer Portal. Without it, the bot gets message events with no text.
The bot answers in DMs and not in channels
The channel routes may be #observe only. Add a verb=mention route that targets main, not main#observe.
discd is unhealthy
The token was rotated, or the bot is not in the guild. Copy the new token into DISCORD_BOT_TOKEN and restart: sudo systemctl restart arizuko_acme.
A WebDAV mount fails
A WebDAV client needs a Bearer token. The browser login works only in the browser.
