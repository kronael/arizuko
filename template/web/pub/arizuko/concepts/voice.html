voice

Voice adds audio without a change to the agent: the agent stays a text process, and the conversion happens at the edges. For voice in, a user sends an audio note, and Whisper turns it into text before the agent reads anything. For voice out, the agent calls send_voice, and the TTS daemon turns the text into an ogg file. The chat platform delivers it as a real voice note. The agent never handles audio. It reads and writes text, and the daemons convert on both sides.

Whisper turns a voice note into text before the agent reads it

When a voice note arrives at an adapter, such as Telegram, WhatsApp or Discord, the adapter downloads the audio and gives it to routd. If WHISPER_BASE_URL is set and VOICE_TRANSCRIPTION_ENABLED=true, routd posts the audio to that Whisper server before the agent sees the message. The transcript comes back as plain text, and routd adds it to the attachment tag in the prompt:

<attachment path="/home/node/media/20260515/note.ogg"
            mime="audio/ogg"
            transcript="hey can you check the inbox">

The agent reads transcript= like any other text and never transcribes again. The raw audio stays on disk in media/<date>/ in case a skill needs the bytes.

send_voice turns text into a voice note

To reply with voice, the agent calls the send_voice MCP tool with the JID of the chat, the text and an optional voice name. routd does the rest:

  1. routd picks the voice. An explicit argument wins. Otherwise, routd uses voice: from the PERSONA.md frontmatter, and otherwise the TTS_VOICE environment variable.
  2. routd hashes the text, voice and model with sha256. If <data_dir>/tts/<hash>.ogg already exists, routd uses it again and synthesizes nothing.
  3. If the file does not exist, routd posts to TTS_BASE_URL at the OpenAI-shaped path /v1/audio/speech. The bundled ttsd daemon forwards the request to a local Kokoro-FastAPI container.
  4. routd gives the ogg file to the channel adapter, which sends it with the native voice message of the platform.

The text limit is 5000 characters. The TTS endpoint is compatible with OpenAI, so to use Piper, Coqui or the OpenAI cloud, change TTS_BACKEND_URL on ttsd.

The persona decides when the agent speaks

The persona decides. A persona built for voice, such as an assistant used only by phone, always speaks. A persona built for text speaks only when the user spoke first. A reply in the same mode is easier for the user than audio for every message. The agent makes the choice from its instructions, and the system converts nothing automatically.

Two failures have two different results

With TTS_ENABLED=false on the instance, send_voice returns an “unsupported” error with a hint, and the agent sends plain text with send. If ttsd itself is down, nothing turns voice off for you. routd does not watch the /health of ttsd, so the call fails with a synthesis error, and the agent must send text instead. In both cases the user must get text, not silence, but in the second case the agent decides.
