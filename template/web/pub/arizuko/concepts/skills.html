skills

A skill is a directory of markdown that the agent reads when it needs to do a specific task. It is one more set of files in the ant. The agent ships with a built-in set, and the operator can add more. Skills do not start on their own. A model does not reliably notice that a skill applies, so every turn tells the agent to run /solve, which matches skills through /dispatch. Discovery is a deliberate step.

A skill is one directory with a SKILL.md

A skill is one directory under ant/skills/. Every skill has a SKILL.md with YAML frontmatter and a body:

---
name: skill-name
description: one-line summary; say in prose when the skill applies
---

Skill instructions here...

A name must match ^[a-z0-9\-]+$, and the seeder skips every other name. Next to SKILL.md, the directory can hold reference files such as *.md and executable helpers such as *.sh and *.ts.

Skills come from three sources

Built-in
Everything under ant/skills/ in the arizuko repo, such as self, migrate, diary, find, oracle, persona and visual. The count is 93, measured at commit f0762846c1dfdcc71ea15798cc28ad17ddc6c10d with ls -d ant/skills/*/ | wc -l. They ship inside the arizuko-ant image, and container.seedSkills() copies them into every new group. onboarding describes the copy.
Package
A package can ship a skills/ folder. arizuko generate copies each of its skills into every existing group and overwrites the copy of the group. It skips a skill that the group disabled or whose name a built-in skill already uses.
User
A group can add its own skills under /home/node/.claude/skills/, the group folder mounted in the guest. The agent loads them in the same way. They live in the data directory of the group, not in the image.

Every /migrate run refreshes the built-in skills and never overwrites user skills.

The prompt tells the agent to find its skills

A model does not reliably start a skill from its description. So runed ends every prompt with a [solve] line that tells the agent to run /solve first. /solve classifies the message, recalls the context and then runs /dispatch. /dispatch compares the description of every skill with the request and loads the matches. Without that line, the agent does not use its skills.

The always-loaded file is not the place for these instructions. The agent reads that file on every turn, whether the turn needs it or not. A rule belongs there only for two reasons. The agent needs it before it can know to ask, or a break in it fails without an error. Everything else is a skill, loaded when it applies.

One version number triggers the skill update and the announcement

The agent image carries a version number in ant/skills/self/MIGRATION_VERSION, a single integer. Every release with skill changes increments it. Before each turn, runed compares the version of the image with the last version the group saw:

  • If the image is newer, the prompt carries a [pending migration] line, and the agent runs /migrate. /migrate copies new and changed skill files from the image into .claude/skills/ of the group. It replaces built-in skills and keeps user skills.
  • The same step posts the release announcement. /migrate takes the > blockquote at the top of the new CHANGELOG.md entry and posts it into the chat. The skill update and the announcement travel together, and the version increment is the one trigger.

Each version increment has a matching ant/skills/self/migrations/NNN-vX.Y.Z-summary.md file. The file triggers the announcement, and a release with only doc changes can use a short file.

Related pages cover seeding and shipping

onboarding shows how a group gets its first skills. The “Skills” section of [EXTENDING.md] has the format rules and the layout of a skill. The “Shipping changes” section of [CLAUDE.md] has the release steps that increment MIGRATION_VERSION and add a migration file. changelog lists what each version ships.
