development

The arizuko team builds arizuko with the same parts that route a Slack message: specs, skills, file memory and ephemeral turns. The page describes the build process of the project, not a task for an operator. For the parts themselves, see primitives, the ant and skills.

Agents do the work and keep it as files

Claude Code sessions with durable file memory and bounded subagents do the work. A large change, such as a migration or a refactor across packages, runs in a subagent with its own git worktree, so parallel work does not collide. Edits to the shared tree go one at a time. A turn gives a single folder the same serialization.

Each step of the build loop leaves a file on disk

Design is a spec
A design lands as a file under specs/ with a status: field, such as draft, partial or shipped. You can review and diff it.
A second opinion is one command
codex exec asks an independent model to check a design before the commit.
The decision is written down
/diary records the decision in .diary/<date>.md when it is made.
The next session reads the record
/recall-memories reads the diary and a file memory store to recover the context. A production agent uses the same state primitive: files, not a context window.

A small first version ships, then passes harden it

The first version is small and lands fast. The same agents then harden it with repeated passes:

Two adversaries read the change
codex exec searches the finished code for bugs the author missed. /eval attacks the change from a fixed role, such as a CEO, a CTO or a red team, and looks for the worst weakness.
A sweep finds every other instance
/sweep searches the whole codebase for one class of problem and records each instance, so no call site or reference stays wrong.
Refine cuts until a pass finds nothing
/refine removes duplication and makes the diff smaller. It runs again until a pass finds nothing to change.
A bug is recorded before it is fixed
A finding goes into BUGS.md first, with the measurement that found it. One subagent then fixes it with a test that fails without the fix. A redesign, an action on live data, or a finding with an unmeasured premise stays in the queue until the owner decides.

The four layers are also the build path

The primitives, components, daemons and products stack describes how a change is built, not only the architecture. A concept starts as a spec, becomes a Go package, goes into a daemon and appears in an installable product. The secret broker is one example. It started as a spec and became the secret-resolution code in store and ipc. It runs inside routd, and a product declares it as folder and user secrets.

A new requirement is a spec edit, a package and a route. These are files on a host you control, changed with an edit and a commit.
