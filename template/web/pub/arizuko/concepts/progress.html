live progress

A task with several steps starts with a short task summary. On a compatible channel, that summary opens a thread for the live checklist and the answer.

A task summary opens a thread for the checklist

The summary has a robot mark and does not change:

🤖 Review the log files

The checklist follows inside the thread of the summary. The answer, the files and the voice replies use the same thread. If the request already belongs to a thread, everything stays in that thread. The checklist is one message that changes in place:

⏳ ☑ Read the three log files
☐ Cross-check the timestamps
☐ Write the summary

A minute later, the same checklist message, edited:

⏳ ☑ Read the three log files
⏳ Cross-checking the timestamps
☐ Write the summary

The checklist uses three marks:

☑
Done.
⏳
In progress now. If the plan gives an in-progress wording, such as “Cross-checking the timestamps”, the line shows it. If not, the line shows the plain item text.
☐
Not started.

The ⏳ at the start of the first line changes to ✓ when the turn finishes, or to ✗ when it fails. The task summary keeps its robot mark.

A hook posts the plan, not the model

The agent declares its overall task in the first <status> block, before it plans with the TodoWrite tool. A hook of the harness renders each change of the list into the same editable checklist. The first task of the list never replaces the declared summary. Later status blocks update the progress of work that has no task list.

Later updates edit the first message

The first progress update sends the checklist, and every later update edits it. The stored message rows keep the identity of the checklist, the summary and the thread, so a restart of routd in the middle of a long turn does not lose them.

A queued summary is sent again with its original identity. Until the summary arrives, an answer without a place returns an error and stays out of the retry queue. If the summary read fails or the channel refuses the thread, routd never sends the answer to the parent channel.

The chat shows that the agent is busy until the turn ends

The channel also shows that the agent is busy. Telegram, Discord and WhatsApp use their own typing indicator. Slack and GitHub have no such indicator, so they put an eyes reaction, 👀, on the message that started the turn. The indicator stays on until the turn ends, not until the first reply. So an agent that answers and then continues to work still looks busy. If the adapter restarts during the turn, the reaction stays: the adapter records it and removes it when the turn ends.

Channels that cannot edit show only the answer

An editable channel without compatible thread support keeps one progress message and the normal place for the answer. That channel has no separate summary opener.

Email, Bluesky, LinkedIn and X cannot edit a sent message. On these channels, arizuko drops the status updates, and you get only the answer. A stream of separate “still working” posts is what the checklist exists to avoid, so these channels get no fallback. Google Drive comments behave the same way, because the Drive adapter does not edit its replies.

An edit failure appears as an error. routd never posts a replacement message to hide it.

The summary and the checklist never count as the answer

The summary and the checklist promise an answer, and neither one is that answer. The agent delivers the answer with an explicit tool, such as reply. The terminal text of the agent stays in its transcript. If an addressed turn, or a turn that declared work, ends without a delivery, the agent gets one prompt. If the agent stays silent, a failure notice arrives in the same thread.

Short plans and turns without a plan send no checklist

  • A plan with one step sends no checklist, because a one-item list is noise. A plan with two or more items gets a live message.
  • An agent that answers without a plan sends no checklist. Short turns do not need a plan and do not make one.

A simple reply needs neither a summary nor a checklist.

The code that renders the checklist

The hook that renders the list is in [ant/src/todo-status.ts]. The code that creates or edits the message, and the end-of-turn mark, are in [routd/progress.go]. retries explains what happens when the turn stops before it finishes the list.
