concepts

The concepts pages explain how arizuko works, one idea per page. Read them in order the first time, because each page builds on the page before it, or go straight to the concept you need.

The pages follow the path of a message

The concepts pages are a guided path, not a glossary. You meet the agent and follow a message to it. Then each page adds one layer: who can do what, and how an agent proves who calls. Later pages show where credentials and skills come from, and where the agent lives on the web. Each page holds one idea, takes a minute or two to read, and has one example from a real deployment.

Every page ends with a next link in the same order, so the pager takes you through the whole path. For the full lists, such as every flag, every column or the full JID schema, each concept links to its matching page in reference. Concepts explain the why and the shape. Reference lists the fields.

Thirty pages, in reading order

  1. Primitives: the whole system on one page. Six parts in a fixed order, and how every feature combines them. Read it first.
  2. Development: the team builds arizuko with the same parts it runs: specs, skills, file memory and subagents in worktrees.
  3. The store: where every row lives. One server, one account per instance, one key per daemon.
  4. Scaling: the same code runs solo/inbox and corp/eng/sre/oncall. A new tenant is new rows, not new infrastructure.
  5. The ant: the agent you talk to, a folder with a persona, skills, memory and secrets.
  6. A turn, end to end: one figure of the whole path from the adapter through the router and the guest back to the chat.
  7. Routing: how an inbound message finds the correct agent, through one table that maps JIDs to folders.
  8. Engagement: after a message arrives, whether the bot keeps listening after one mention.
  9. Proactive: the other direction. The agent speaks when nobody addressed it, behind a row of checks and a 24-hour cooldown. It is off until you turn it on.
  10. Topics: one strand of work as its own conversation inside one folder.
  11. Live progress: the checklist you see while the agent works. One message, edited in place, posted by the harness and not by the model.
  12. Retries: what happens when the guest that runs your turn stops before it answers.
  13. Onboarding: how a new group and its members get in: invites, the admission queue and SetupGroup.
  14. Autoviv: how a new chat gets its own folder and agent on first contact, with no manual step.
  15. Personas: the voice and standing instructions of an agent.
  16. Auth: how arizuko knows who calls: OAuth, local login, account linking and one canonical sub.
  17. Grants: what that principal can do, read from the acl table on every call.
  18. Scopes: the folder tree that grants use, which folder sees which, and where isolation starts.
  19. Secrets: model credentials in the environment of the guest, and capability credentials used on the host.
  20. Connectors: the API of another service as an agent tool, with the credential kept on the host.
  21. Audit trail: the row that every change writes in the same transaction as the change, and which daemon keeps it.
  22. Skills: markdown instructions that the agent loads when it needs them.
  23. Tasks: scheduled and recurring runs: cron, interval, one-time and autonomous work.
  24. Workflows: the discipline that makes jobs with many steps converge: free conversation, a strict opening and one plan file.
  25. Tokens: route tokens that let a public chat box or a webhook reach an agent without a login.
  26. Web-native agents: the web content that a folder owns: a public page, an embedded chat and form intake.
  27. WebDAV: the file workspace that you can mount with rclone or reach with curl.
  28. Voice: voice in and out. Whisper transcribes, and the agent decides when to speak back.
  29. Slack pane: the Slack assistant sidebar with a title, suggested prompts and pane context.
  30. Addressing (JID): the one address shape for every chat and sender on every adapter.

Setup commands are in how-to, and complete option tables are in reference. When you are ready to build, start with getting started.
