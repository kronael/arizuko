arizuko v0.70.9 — 23 October 2026

A turn now stays open while its background agents work, so their results no longer arrive after the session closed.

  • Sessions — a claude session ends when its work is done and Claude Code is idle; one submit_turn posts the result.
  • Background agents — a Stop no longer ends the turn while background tasks run.
  • Deadline — one process deadline covers every run, and the agent gets a [deadline] note 60 seconds before it.
  • Steering — steering lines reach a waiting session and no longer go to subagents.

arizuko v0.70.0 — 5 October 2026

Docker has left the turn path: every turn now boots its own virtual machine, and egress isolation stopped being a setting an operator can leave empty.

  • One KVM guest per turn — runed boots the release’s own kernel, exports the turn’s files over virtio-fs and reaches the guest over vsock. The folder, the skills and the session history arrive at the same paths as before.
  • Egress cannot be off — the guest’s one interface is a tap whose rules accept its own proxy and drop everything else, and runed refuses to start without the proxy binary. EGRESS_IMAGE and its three companions are gone.
  • No resolver in the guest — a host name is only meaningful inside a request to the proxy, which closes the UDP/53 side channel by construction. IPv6 is taken off the tap before the link comes up.
  • The turn’s credential is the guest’s vsock CID, a host-kernel fact a guest cannot forge, in place of the container’s uid.
  • 2800 lines net gone in one commit — the Docker runtime, the per-folder network carve, the proxy-container lifecycle, RUNED_SUBSTRATE, CONTAINER_IMAGE and the docker socket.
  • The web server idles at 0% and a third of the memory — it watches pages with inotify instead of polling 48k files, and reference clones left the public tree; a group’s web slot holds pages only.
  • routd and dashd publish on loopback only, and the instances’ host ports move above 49000; only proxyd faces the network.

arizuko v0.62.0 — 28 July 2026

Channel adapters are plain docker compose files now, and a package manager installs a whole integration — fragment, routes, grants, skills — from a git source.

  • Native compose packaging — each adapter ships as template/services/<name>.yml, a partial compose file docker includes verbatim. Per-adapter proxyd routes move to a sibling <name>-routes.json. The custom TOML mini-format and the PROFILE var are gone; optional daemons run via COMPOSE_PROFILES, which arizuko generate derives from the feature flags. Existing data dirs auto-convert their services/*.toml on the next generate. Spec 5/27.
  • Package manager — arizuko packages install | upgrade | remove | list installs a git-or-local package that bundles compose fragments, proxyd routes (hot-applied to the live proxyd_routes table, no restart), grants, and skills. Each install writes an installed-package record (source + revision + owned assets + per-asset hash); upgrade refuses a locally edited asset instead of overwriting it; remove withdraws routes before dropping fragments. Installed packages show at /dash/packages/. See the packages reference. Spec 5/28.

  • Thread-scoped history (get_thread MCP) — pull just one topic out of a chat’s history; tier-gated like inspect_messages.
  • External agents over slink (POST /slink/<token>/mcp) — register a token-bound URL as a remote MCP server in Claude Code or any MCP client; three group-scoped tools (send_message, steer, get_round). Token is the auth.
  • OAuth account linking (/dash/profile) — one canonical sub across providers, with a collision-resolution UX when a new OAuth identity doesn’t fit silently.
  • Typed JID routing — telegram:group/* scopes to groups but not DMs; sign-bit guessing retired across the router and grants tables.
  • Idle-timeout default raised to 60 min — stops mid-turn container kills caused by stale per-instance overrides reading 60 ms.

arizuko v0.32.1 — 30 Apr 2026

Quiet bugfix release. Closes a cross-world spam vector revealed by v0.32.0’s own release broadcast: tier-1 world agents could send to chats that route to other worlds, producing the same notice 2–4× per chat.

  • Outbound MCP authorization — every send-shaped tool (send, send_file, reply, post, like, dislike, delete, edit, forward, quote, repost) resolves the JID’s owning folder and checks subtree containment. No tier bypass; even the instance root cannot direct-send across worlds.
  • Inter-world communication goes through delegate_group/escalate_group instead. Unrouted JIDs are denied for every caller.

arizuko v0.32.0 — 30 Apr 2026

Slink becomes the universal “drop a message, observe the round” surface. Every agent run is now a first-class object with a stable handle, pageable frames, an SSE stream that closes cleanly, and steering for chained follow-ups — useful for cron jobs, web pages, and scripts that need to talk to the agent without a full chat client.

  • Slink round-handle protocol — POST /slink/<token> returns {user, turn_id, status:pending}; the round is observable via snapshot, cursor paging, cheap status, or live SSE with a terminal round_done event.
  • Steering — inject a follow-up onto an in-flight round; per-folder queue serialization makes it the immediate next round, with chained_from linking the two.
  • arizuko send CLI — inject messages from the server into any group via slink; --wait, --stream, --steer flags.
  • Public web docs at /pub/concepts/slink.html and /pub/slink/reference/.
  • Group state machinery removed — no more closure-then-archive cycle, no spawn_ttl_days, no daily cleanup loop. Groups exist until explicitly removed.
  • Crackbox DNS & davd healthcheck fixes rolled in from v0.31.1 — per-folder networks now resolve crackbox; davd reports health.
