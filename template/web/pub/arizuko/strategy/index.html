comparable systems

The systems that overlap with arizuko on channels, tenancy, isolation or memory, and how each one differs.

Systems · Limits

Each comparable system does a part of the job

Each line says how the system differs from arizuko. The agents hub on krons at https://krons.fiu.wtf/pub/krons/agents/ reads the source of many of them, and https://krons.fiu.wtf/pub/krons/agents/comparison/ compares five side by side. krons at https://krons.fiu.wtf is the reference deployment of arizuko.

Personal agent gateways serve one operator

SystemAddressHow it differs
OpenClawhttps://github.com/openclaw/openclawA personal assistant on many chat platforms from one Node.js process. An agent is a row in its config. A Docker sandbox for tools is optional, and no VM runs a turn.
NanoClawhttps://github.com/nanocoai/nanoclawA small rewrite of the OpenClaw model. The Claude Agent SDK runs in one container per session, and a per-session SQLite file is the only channel to the host. arizuko runs each turn in its own KVM guest and reaches the host through an MCP socket.
Muaddibhttps://github.com/pasky/muaddibA chat assistant for teams that runs tool calls in QEMU micro-VMs. The model SDK and the web tools run on the host, and all users of a channel share one VM.
ElizaOShttps://github.com/elizaOS/elizaA framework with character.json personas and a plugin marketplace. Agents run in the host process with no sandbox, and memory is PostgreSQL with pgvector.
Miladyhttps://github.com/milady-ai/miladyElizaOS as a desktop and mobile app for one person, local first.
Hermes Agenthttps://github.com/NousResearch/hermes-agentA long-running Python agent that writes its own skills and scans skills for threats. One process keeps a session across many turns, with no VM per turn.
takopihttps://github.com/banteg/takopiA Telegram bridge to the coding CLIs Codex, Claude Code, OpenCode and Pi, with one git worktree per branch. One operator and no tenants.
Lettahttps://github.com/letta-ai/letta
https://github.com/letta-ai/letta-code		A server for agents that keep memory across runs, local or in Letta Cloud. letta-code sends replies only through a message tool, for one operator with no tenants. An arizuko turn delivers its final text block.
brainprohttps://github.com/jgarzik/brainproA Rust coding assistant that sends each kind of task to a different model provider. A chat pairs to a session with a code, and no sandbox runs the tools.
HOME23https://github.com/notforyou23/home23An agent that runs all the time in continuous loops. An arizuko agent runs only during a turn.

Team harnesses keep a sandbox per scope or per thread

SystemAddressHow it differs
qmhttps://github.com/yc-software/qmA multiplayer agent harness in Slack and on the web, hosted in the cloud account of the team. It keeps one durable sandbox per scope, filters egress with Envoy and uses MCP servers without serving one. Its scopes are five flat kinds, where the path of an arizuko folder has no depth limit.
Centaurhttps://github.com/paradigmxyz/centaurSlack agents in one Kubernetes pod per thread, a workflow engine that replays steps, and a proxy that adds credentials on the wire. arizuko has no workflow engine. routd runs a turn that fails without a reply again, up to MAX_TURN_RETRY times, default 3.
OpenClaw Managed Agentshttps://github.com/stainlu/openclaw-managed-agentsAn open implementation of the Anthropic Managed Agents API over one Docker container per session. The API has four nouns: agent, environment, session and event.
Cloudflare Agentshttps://github.com/cloudflare/agentsAn SDK for agents that run as Durable Objects on Cloudflare, each with its own SQLite state. Cloudflare runs the platform, where arizuko runs on a host you own.
Dusthttps://dust.tt/A hosted service for agents over company data, with many data connectors. arizuko has no connector sync and is not a hosted service.
Zapier Agentshttps://zapier.com/agentsHosted agents that act through the app integrations of Zapier.

Frameworks and builders leave the hosting to you

SystemAddressHow it differs
LangGraphhttps://github.com/langchain-ai/langgraphA library for agent programs as graphs. You write the service, the channels and the tenancy.
AutoGenhttps://github.com/microsoft/autogenA framework from Microsoft for conversations between several agents in one program.
CrewAIhttps://github.com/crewAIInc/crewAIA Python framework for crews of agents with roles that work on one task, and a hosted enterprise product.
smolagentshttps://github.com/huggingface/smolagentsA small Python library in which the agent writes its actions as code.
Fluehttps://github.com/withastro/flueA TypeScript agent framework that runs tools in an in-memory virtual shell by default. A container is an option, not the default.
Difyhttps://github.com/langgenius/difyA visual builder for LLM apps, workflows and retrieval. An agent is a node in a graph, not a folder.
Flowisehttps://github.com/FlowiseAI/FlowiseA visual builder for LLM flows.
n8nhttps://github.com/n8n-io/n8nWorkflow automation with AI agent nodes. An agent is a step in a workflow.

Adjacent tools share one part of the shape

SystemAddressHow it differs
Aeonhttps://github.com/aeonfun/aeonAgents that run skills on GitHub Actions on a schedule and commit their state to git. A run is a scheduled job, not an answer to a chat message.
Autolithhttps://github.com/lambda-symbolics/autolithA Common Lisp agent that changes its own running image and can roll it back. arizuko keeps no live image: each turn boots a new guest.
Entirehttps://entire.io/A git host that links each agent session to the commit it made. arizuko is not a git host.
Onyxhttps://github.com/onyx-dot-app/onyxSelf-hosted search and chat over company documents, with connectors. It does the retrieval that arizuko does not do.

Four limits of arizuko are open

LimitWhat is true now
The runed container is not locked downCompose runs runed as root with NET_ADMIN, SYS_ADMIN and apparmor=unconfined, because the default AppArmor profile denies the mount(2) calls of the staging tree. The turn itself runs in a KVM guest. No narrower AppArmor profile for runed is written.
No cluster has run the Helm chartThe chart in deploy/helm/arizuko/ passes helm lint and helm template. It runs routd and runed as one replica each on the node that holds the data volume.
No trace viewerEvery daemon exports OTLP logs and spans when OTEL_EXPORTER_OTLP_ENDPOINT is set. The collector and the viewer belong to the operator.
No loop judges finished turnsanteval runs eval suites when an operator starts it. No daemon scores a turn after the turn ends.

Design directions for arizuko live in the specs/ directory of the repository. A spec that is folded into the docs is deleted and stays in git history: git log --diff-filter=D --name-only -- specs/.
