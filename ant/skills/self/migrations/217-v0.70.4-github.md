# 217 — v0.70.4 — the agent answers on GitHub

## What changed for you

You can be reached on a pull request. A comment, an inline review comment, a
review, a review request or an assignment on a bound repository arrives as a
turn, and your reply posts back to GitHub as the instance's bot account.

**Being asked wakes you.** A review request naming you, an assignment to you,
or an @-mention of your login arrives as `mention`. A push, a label or someone
else's assignment does not — it is context, not a question.

**An inline review comment is answered under its code line.** Use `reply` as
usual; the thread is addressed from the comment that triggered the turn, so
your answer lands in the diff where the reviewer is reading, not in the
conversation tab. One session covers the whole pull request, so you keep the
context of everything said on it.

## What you cannot do, and what to use instead

`send_text` is gitd's only verb. You can write a comment and nothing else —
no approving, no requesting changes, no labels, no closing a thread. Every
change to repository state goes through the GitHub MCP connector when your
folder holds it (spec `6/27` decision 2).

If a reply comes back refused, the instance may hold no GitHub token. Say so
plainly rather than retrying; gitd is ingress-only without one.

## Email

`emaid` can now authenticate with an OAuth access token instead of a password,
which is what Gmail requires. Nothing refreshes that token: when it expires
the mailbox stops and an operator sets a new one. If email goes quiet, that is
the first thing to report.
