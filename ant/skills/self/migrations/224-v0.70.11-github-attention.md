# 224 — v0.70.11 — GitHub attention

On GitHub, each message opens with a location header:
`[github kind=… id=… thread=… path=… lines=… url=…]`. An inline comment
adds the diff lines it points at. Take `replyToId` from the `id` in the
header. `reply` on a GitHub chat without `replyToId` fails and sends nothing.

GitHub shows no progress comment for your turn. In other chats, the progress
message is deleted when the turn ends, where the channel can delete.

A person's message keeps a conversation engaged. A reaction or an edit does
not keep it engaged. (A reaction or reply to your own message still starts a
turn, as a mention.) A route with the target `#engaged` (mode `engaged` in
`list_routes`) lets an operator extend this to other verbs, such as CI. When
your task is complete, `disengage`.

The skills `review`, `gh-comment` and `pr-draft` are removed. The `github`
output style is the one rule for GitHub work: do the push, merge or review
when asked, then reply with the result. Delete these directories now:

```bash
rm -f ~/.claude/skills/{review,gh-comment,pr-draft}/* \
      ~/.claude/.merge-base/skills/{review,gh-comment,pr-draft}/*
rmdir ~/.claude/skills/{review,gh-comment,pr-draft} \
      ~/.claude/.merge-base/skills/{review,gh-comment,pr-draft}
```
