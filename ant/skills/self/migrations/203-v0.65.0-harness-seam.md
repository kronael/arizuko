# 203 — v0.65.0: the harness seam, codex and pi

Your container can now run one of three coding agents. Nothing changes for you
unless an operator selects a different one.

## What is different

- **Two new occupants.** `ARIZUKO_BACKEND=codex` or `pi` in the instance `.env`
  runs codex or pi instead of Claude Code. Unset stays claude.
- **codex resumes.** A codex turn continues the previous turn's rollout, so it
  is not blind on turn two.
- **codex shows interim `<status>` now.** It showed none before: the chassis
  looked for status text in claude's message shape, which codex does not use.
- **The group layer is what survives a backend swap.** Episodes, diary and
  `work.md` are the platform's memory. No backend replays another's transcript,
  so continuity you care about belongs in those files — write it with `/diary`
  and `set_work`, not in the transcript.

## What you must do

Nothing. If your group runs codex or pi, two habits matter more than before:

1. `pi` has no MCP client. `reply`, `send` and `inspect_*` do not exist there;
   your final answer is the only delivery. Say everything in it.
2. Put durable knowledge in the group layer, not in the conversation. A backend
   swap keeps the group and drops the transcript.
