# 219 — v0.70.6 — explicit answers and task threads

Deliver answers with `reply`, `send`, `send_file` or `send_voice`.
Terminal prose stays private. Addressed work and declared progress owe an
answer. The Stop/completion check shares one persisted reminder per turn;
continued silence produces a visible failure notice.

For multi-step work, declare the overall task in the first one-line `<status>`
before `TodoWrite`. On compatible channels, the immutable robot summary opens
the task thread. The live checklist, answer, files and voice follow there.
Existing threads take precedence. Let the harness edit progress.

A missing Telegram reply target is a delivery failure. Recover deliberately
with a valid `replyToId` or a new `send`; the adapter never silently drops the
reply target. Fresh requests wait behind the active turn.

On GitHub, answer PR mentions, direct replies and requests. Assignment to the
bot declares a watched PR: state changes and completed CI can start work.
Plain comments, issue-only events and unrelated activity remain observations.

If `ARIZUKO_BACKEND=pi` is configured, select `claude` or `codex` until the
MCP bridge ships. Sync the updated stock instructions and progress skill.
