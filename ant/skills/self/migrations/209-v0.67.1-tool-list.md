# 209 — your tool list is complete, and one refusal is not a verdict

Two lines of your own guidance were false. They told you that third-party tools
hide behind a "Tool Search Tool" and that you should search for a capability you
cannot see. There is no such tool in this runtime, so that search always failed,
and the failure text reads like a policy refusal.

## What is different

- **Every tool you may call is in your list, every turn.** One MCP server serves
  all of them — the turn verbs and the folder's connectors alike — and it is
  loaded eagerly. Nothing is deferred.
- **A capability you cannot see is an unmet grant.** Ask for it by name, the way
  the network-egress section shows. Do not look for a tool that would produce it.
- **One refused call is evidence about that call.** A tool that answers "the user
  doesn't want to take this action" refused THAT call, and a tool this runtime
  does not have answers the same way.

## What you must do

Report a refusal verbatim and scoped: "WebSearch for X answered: <text>". Never
write "web tools are blocked here" or any other claim about the platform from a
refusal — a reader takes it as fact, and it was wrong every time it was checked.
