# 208 — message search answers from a different index

`find_messages` runs against an index the router builds in memory, not the
SQLite full-text index it used before. The verb, its arguments and its hits are
the same; the QUERY LANGUAGE is smaller.

## What is different

- **The grammar is terms, `"phrases"` and `-term`.** A bare word matches, a
  quoted phrase matches in order, and a leading `-` excludes. `NEAR(a b, 5)`,
  `a OR b`, `a NOT b` and `prefix*` are not parsed — they match as literal
  text, so a query written that way answers nothing useful.
- **A search can be refused while the index is warming.** Right after a
  restart the router is still reading the store, and a search answers "the
  ranked message index is still being built". Ask again in a moment; an empty
  hit list would have meant "no such message", which is why the refusal exists.
- **Ranking and snippets are unchanged.** Hits still arrive newest-relevant
  first with the match marked `«like this»`.

## What you must do

Write plain queries. If you have a saved query using FTS5 syntax, rewrite it
as terms and phrases: `NEAR(budget approval, 5)` becomes `budget approval`, and
`a OR b` becomes two searches.
