# Go 1.27 adoption

arizuko's `go.mod` declared `go 1.25.5` when this was written (it now
declares `go 1.27` + `toolchain go1.27rc2`). Go 1.26 shipped GA in February
2026 (now at 1.26.5) and the repo has adopted none of it. Go 1.27 is
**not released** — as of 2026-08-02 it is at `go1.27rc2`
(go.dev/dl), and go.dev/doc/go1.27 itself is still headed "Go 1.27 is
not yet released. These are work-in-progress release notes." Go's
release cadence puts GA around six months after 1.26 (August), so 1.27
may land within weeks of this spec — but it has not landed, and its
API surface (frozen at RC, not final) should not become a toolchain
floor before GA. This spec is honest about that split:

- **Go 1.26** — GA, stable, adoptable today. Two real wins (§2, §3)
  plus free runtime/GC improvements from the bump alone. §3 has
  **already shipped** — it needed no bump at all (see below).
- **Go 1.27** — RC2, not GA. Three small, concrete wins (§4).

**Everything here has now shipped.** The repo went straight to
`go 1.27` on the `go1.27rc2` toolchain rather than staging through
1.26 — steps 1-2 were retargeted to 1.27 and landed with step 4. The
"wait for GA" guidance below was overruled by the operator; §4 records
the RC pin and the debt it creates. The analysis is kept as written
because the reasoning still explains _why_ each swap is safe.

Every feature below is cited to its go.dev/doc/go1.2{6,7} section and
mapped to a real file:line in this repo. Where research turned up no
call site, the feature is listed under "explicitly not adopted"
instead of padded into the plan.

Almost every fix here targets a **pre-1.26** language feature the
repo simply never back-filled — the new thing in 1.26 is `go fix`
itself being the tool that finally surfaces them in one pass (go1.26
Tools, "go command: go fix Revamp"). Net effect: dozens of files
touched, ~-70 to -80 LOC, most of it in `slices.Contains`/`maps.Copy`
collapses; the rest is idiom churn with no LOC delta but real
robustness gains (`atomic.Int32` vs. hand-paired `int32` +
`atomic.AddInt32` calls removes a whole bug class in test helpers).

## Ship plan

Each step is independently shippable and commit-sized. All four have
shipped; steps 1-2 landed retargeted to 1.27 (see §4), so the 1.26
figures below are the original analysis, not what was committed.

### 1. Bump the toolchain floor — SHIPPED as 1.27 (`5eab62ed`)

Planned as `go 1.25.5` → `go 1.26.0` with `Dockerfile:4`
`golang:1.25-alpine` → `golang:1.26-alpine`; shipped straight to
`go 1.27` / `golang:1.27rc2-alpine` instead. No other code change —
this step alone buys Green Tea GC by default (10-40% GC overhead
reduction, go1.26 Runtime), ~30% lower cgo call overhead (the
`cmd/arizuko` binary is the one `CGO_ENABLED=1` build, `Makefile:28`),
and `io.ReadAll` ~2x faster / less alloc (76 call sites across the
repo, `net/http` bodies and attachment downloads included) — all free,
zero-diff wins from the bump.

CI needs no change: `.github/workflows/ci.yml:17,54` already use
`actions/setup-go@v5` with `go-version-file: go.mod`, which tracks the
directive automatically.

Verify: `make build && make lint && go test ./... -short`

### 2. Replace `obs/handler.go`'s hand-rolled fanout with `slog.NewMultiHandler` — SHIPPED (`71d1fa45`)

Depends on step 1 (`NewMultiHandler` is a go1.26 symbol). Delete
`obs/handler.go` (33 lines). In `obs/obs.go:62`, replace
`slog.New(&fanout{stderr: stock, otel: bridge})` with
`slog.New(slog.NewMultiHandler(stock, bridge))`. Verified
behavior-equivalent: `slog.Logger` discards whatever `Handle` returns
(documented), so `MultiHandler`'s `errors.Join`-of-both-handlers
return value vs. today's swallow-OTel-errors-only behavior is not
observable anywhere in the codebase.

Verify: `go test ./obs/... -v` (covers the fanout-record test at
`obs/obs_test.go:84`), then `make lint && go test ./... -short`

### 3. Run the `go fix` modernizer sweep — SHIPPED (`a5645e4d`, 2026-08-02)

Shipped ahead of steps 1-2, which is the point: every fix targets a
pre-1.25 idiom, so none of it needed the toolchain bump. Verified by
building and vetting the result under `GOTOOLCHAIN=local` (go1.25.5).
Landed 130 files, -95 net LOC; `go test ./... -short` 52 ok / 0 fail.
The `atomic.Int32` conversions in test helpers are the quiet win — they
retire a hand-paired `int32` + `atomic.AddInt32` misuse class.

The command was: `go run golang.org/x/tools/gopls/internal/analysis/modernize/cmd/modernize@latest -fix ./...`,
review the diff, exclude `third_party/` if the tool touches it
(it didn't in the dry run — 0 findings there), commit as
`[refined] go fix modernizer sweep`.

`make test-all`'s Go half is green. Its playwright half has one
failure (`services.spec.ts:32`) that reproduces on a clean tree —
pre-existing and unsatisfiable as written; `BUGS.md` D6.

### 4. Adopt Go 1.27 — SHIPPED on `go1.27rc2` (`5eab62ed`, `71d1fa45`, `3b7c605b`, 2026-08-02)

Shipped ahead of GA at the user's explicit direction, overruling this
spec's own "wait for the GA tag" guidance below. **The floor is an RC:
`go.mod` carries `go 1.27` + `toolchain go1.27rc2`.** Once `go1.27.0`
is tagged, move the floor to `go 1.27.0`, drop the `toolchain` line,
and repoint both Dockerfiles at `golang:1.27-alpine`.

Steps 1-2 of this plan were retargeted from 1.26 to 1.27 and landed
with it, so the whole spec ships in three commits:

- **`5eab62ed` — toolchain.** The `go` directive rejects an `rc`
  string; `go 1.27` + `toolchain go1.27rc2` is the accepted form, and
  `go1.27rc2` does satisfy the `1.27` floor (verified by building, not
  assumed). Docker base is **`golang:1.27rc2-alpine`** — the only 1.27
  alpine tag published; `golang:1.27-alpine` does not exist until GA.
  `crackbox/Dockerfile` copies the root `go.mod` and bumps in lockstep.
  `INSTALL.md` prerequisite moved to 1.27 with the RC-fetch note.
  **Forced dependency bump:** `golang.org/x/net` v0.54.0 → v0.57.0.
  v0.54.0 gates `http2/server.go` behind `!(go1.27 && !http2legacy)`,
  so `http2.TrailerPrefix` disappears under 1.27 and `grpc` v1.80.0
  fails to compile; v0.57.0 moves the const to an untagged
  `server_common.go`. Any 1.27 bump needs this — it is not optional.
- **`71d1fa45` — `slog.NewMultiHandler`.** `obs/handler.go` deleted
  (33 lines). Both semantic deltas were checked against the go1.27rc2
  source: the `errors.Join` return is unobservable (the only `Handle`
  calls were inside the deleted file, no `slog.NewLogLogger` exists,
  and `Logger.log` discards the return), and `MultiHandler`'s
  enabled-only dispatch changes nothing because the bridge resolves
  through the OTel SDK to the single wired `BatchProcessor`, whose
  `Enabled` returns unconditional `true`.
- **`3b7c605b` — stdlib swaps.** stdlib `uuid` at 3 sites; 8
  `strings.CutLast` conversions; 4 redundant HTTP drains deleted
  (`emaid/imap.go` untouched — IMAP part bodies, different code path).

Two findings that corrected this spec's own claims:

- **`uuid` was not uniformly call-compatible.** `authd/store.go:183`
  called `uuid.NewString()`, which the stdlib package does not provide
  (it has `New`/`NewV4`/`NewV7`/`Parse`/`MustParse`/`Max`/`Nil` only).
  It was rewritten to `uuid.New().String()`.
- **`google/uuid` does not leave `go.mod`.** It demotes from a direct
  require to `// indirect`: `mark3labs/mcp-go/server` still requires it.
- **`routd/steer.go:526` guarded `sep > 0`, not `>= 0`.** A literal
  `CutLast` swap would newly admit an empty parent for a
  leading-slash folder, so the conversion carries an explicit
  `parentFolder != ""`. All 8 conversions were checked with a
  differential harness over 21 edge-case inputs; old and new agree
  on every one.

Verified: `make build` + `make lint` green, `go test ./... -short`
52 ok / 0 fail, and the full non-short suite across all 11 touched
packages 11 ok / 0 fail. The 301→307 `ServeMux` change (see below)
needed no code change: `webd`/`proxyd` have no test asserting 301, and
`webd/server.go:286`'s 301 is an explicit hand-written legacy redirect,
not a mux trailing-slash redirect.

`make test-e2e` is **vacuous** and did not verify anything here: it
runs `go test ./webd/... -run E2E`, and `webd` contains no test whose
name matches `E2E` (the repo's `E2E` tests live in `crackbox/test/`
and `teled/e2e_test.go`). Pre-existing, unrelated to this spec, filed
in `BUGS.md`. The touched routing-adjacent packages were covered by
running their full suites directly instead.

## What we explicitly do NOT adopt, and why

- **`encoding/json/v2` API (explicit `Marshal`/`Options` calls).**
  The free win — v1 `encoding/json` becomes v2-backed automatically
  once built with go1.27, "unmarshal significantly faster" — lands
  from the step-4 toolchain bump alone, zero code change. Migrating
  MCP/REST call sites to the v2 API to opt into its _stricter_
  defaults (rejects invalid UTF-8, rejects duplicate JSON object keys)
  is a real behavior change on every inbound adapter payload and
  agent tool-call arg — a compat risk with no measured upside here.
  Not proposed.
- **`goroutineleak` pprof profile.** No `net/http/pprof` mount exists
  anywhere in the repo today, and no goroutine-leak bug is on record
  (`BUGS.md` "leak" hits are all data/security leaks, not goroutine
  leaks). Wiring pprof is an orthogonal ops decision, not a version
  adoption; nothing to point at.
- **`testing/synctest`.** Zero current usage, and no flaky
  time-based test was found to retrofit it onto. Worth revisiting the
  next time a `time.Sleep`-based test flakes, not as a speculative
  addition.
- **Generic methods, struct-literal-any-selector-key, function type
  inference (go1.27 language changes).** No generic type hierarchy in
  arizuko needs a method-level type parameter or a nested-field struct
  literal key. No call site.
- **`crypto/mldsa`, `crypto/hpke`, `simd`/`simd/archsimd`.** No
  post-quantum signing requirement, no SIMD-shaped hot loop (routd
  dispatch and SQLite access are I/O- and lock-bound, not
  vector-arithmetic-bound).
- **`net/http.ServeMux` 301→307 trailing-slash redirect (go1.27).**
  Not an adoption, a compatibility note: once step 4 lands, `webd`
  and `proxyd`'s mux-based trailing-slash redirects change status
  code. 307 preserves method+body (strictly more correct than 301 for
  non-GET), and neither daemon relies on 301-specific caching
  semantics — flag for awareness during step 4's e2e run, no code
  change needed.
- **`errors.AsType`, `reflect.Type.Fields()` iterator adoption as
  dedicated steps.** Real call sites exist (table above) but the
  per-site LOC delta is 1 line and neither is covered by the
  automated `go fix` sweep. Bundling them into step 3 or 4 is fine if
  a future pass touches those files anyway; not worth a standalone
  commit.

## Toolchain floor cost

Raising `go.mod`'s directive raises the _minimum_ toolchain anyone
building arizuko needs — contributors, CI, and the Docker build stage
all move together, but not for free:

- **Local builds**: Go's default `GOTOOLCHAIN=auto` auto-downloads a
  matching toolchain on first `go build`/`go test` if the installed
  one is older, so most contributors see this as a one-time network
  fetch, not a manual reinstall. Air-gapped/offline builds don't get
  that fetch — `INSTALL.md`'s prerequisite version needs bumping
  alongside `go.mod` so offline setups aren't surprised.
- **CI**: zero config change (`go-version-file: go.mod` already
  tracks it) — but the bump is still a real CI toolchain change,
  worth watching the first post-bump run.
- **Docker**: `Dockerfile:4`'s `golang:X-alpine` base is a hand-pinned
  string, independent of `go.mod` — the two must be bumped together
  or the build silently uses a mismatched toolchain until noticed.
  Both steps 1 and 4 above bump `go.mod` and `Dockerfile` in the same
  commit for exactly this reason.
- **Step 4 shipped on the RC, overruling this spec.** The argument
  against it stands on its own terms — an RC is not a support channel,
  and CI plus both Docker bases now pin `go1.27rc2`. The operator
  accepted that cost deliberately. `go1.27rc2` is feature-frozen per
  Go's release process (only bugfixes land between rc2 and GA), which
  is what makes the position defensible: the API surface adopted here
  will not move under us. **Outstanding debt:** move the floor to
  `go 1.27.0`, delete the `toolchain` line, and repoint `Dockerfile:4`
  - `crackbox/Dockerfile:1` at `golang:1.27-alpine` when GA lands.
- **Rollback**: each step is one revertible commit. Step 2 depends on
  step 1's bump (revert together); steps 3 and 4's code changes have
  no cross-step dependency and revert independently.
