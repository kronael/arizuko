Verify the rollout:

  kubectl -n {{ .Release.Namespace }} get pods -l app.kubernetes.io/instance={{ .Release.Name }}
  kubectl -n {{ .Release.Namespace }} rollout status deploy/{{ include "arizuko.fullname" . }}-routd
  kubectl -n {{ .Release.Namespace }} rollout status deploy/{{ include "arizuko.fullname" . }}-runed

Check routd's health from inside the cluster:

  kubectl -n {{ .Release.Namespace }} run -it --rm curl --image=curlimages/curl --restart=Never -- \
    curl -s {{ include "arizuko.daemonURL" (dict "ctx" . "daemon" "routd") }}/health

runed runs on a node with /dev/kvm, /dev/vhost-vsock and /dev/net/tun, as root,
with NET_ADMIN + SYS_ADMIN and AppArmor unconfined, and refuses to start while any
precondition is unmet — it names every one in its first log lines:

  kubectl -n {{ .Release.Namespace }} logs deploy/{{ include "arizuko.fullname" . }}-runed

The store at {{ .Values.store.url }} must already hold the owner tables (one-time
`extenddb init`, INSTALL.md § The store server), and the data volume must be seeded
once with `arizuko create`.
